## 一、总体审阅结论

当前文档整体质量较高，结构合理，具有实际开发价值。建议保留 v0.1 的主体内容，不需要推倒重写。

尤其值得保留的经验包括：

- L-001：验收结果必须由证据计算，不能由开发者自行宣告。
- L-003：网页发送和完成状态必须证明属于本轮任务，不确定时先对账，避免误重发。
- L-004：跨进程互斥应使用操作系统级机制，避免反复使用文件内容仲裁。
- L-006：GPT 审查会话主动轮换，优先通过 Git 固定交接，而不是依赖摘要继承。
- L-008：长回复入站与出站规则必须区分。
- L-010：独立审查必须主动寻找反例，不能只验证正向路径。
- L-011：测试程序、日志和证据本身也必须纳入验收。

这些经验具有长期参考价值。

## 二、建议补充的四项机制

### 1. 增加适用范围标签

建议每条经验增加 `scope` 字段，区分：

- `GLOBAL`：适用于所有项目的通用经验。
- `AIEO`：仅适用于 AIEO 项目的经验。
- `TOOL_SPECIFIC`：特定工具或软件的使用经验。
- `ENVIRONMENT_SPECIFIC`：特定操作系统、网络或运行环境的经验。

目的：防止把 AIEO 的专项参数和实现细节直接推广到所有项目。

例如：
- AI 不能连续重复无效修复，属于 GLOBAL。
- AIEO 的 1200 UTF-8 字节限制，属于 AIEO。
- PowerShell `FileShare.None`，属于 TOOL_SPECIFIC。
- Linux Sakura VPN 的 90 秒检测间隔，属于 ENVIRONMENT_SPECIFIC。

### 2. 增加经验有效性状态

建议每条经验增加 `status` 字段：

- `ACTIVE`：当前有效。
- `NEEDS_VALIDATION`：尚待验证。
- `SUPERSEDED`：已经被新方案替代。
- `INVALID`：已经失效。

目的：避免旧经验长期保留，却被 AI 当作当前仍然有效的规则。

经验发生变化时，应记录替代原因和对应的新方案，保留历史，不要直接抹掉失败记录。

### 3. 增加 AI 能力边界记录

建议增加一个独立章节，记录 AI 在实际开发中的能力表现。

建议记录字段：

| 字段 | 内容 |
|---|---|
| 模型/工具 | 实际使用的 AI 模型或开发工具 |
| 任务类型 | 架构设计、代码实现、调试、审查等 |
| 失败表现 | 具体出现了什么问题 |
| 瓶颈判断 | 上下文、工具能力、推理、执行环境等 |
| 最终解决方式 | 换模型、换工具、人工介入或调整方案 |
| 可复用经验 | 后续如何避免类似问题 |

注意：

不要永久给某个模型贴上能力标签。模型能力会变化，结论必须基于具体任务和实际证据。

### 4. 增加跨项目经验迁移机制

建议明确以下原则：

1. AIEO 专项经验首先留在 AIEO 文档中。
2. 经过验证、确实具有普遍性的经验，才可以提炼到通用《AI 软件工程标准》。
3. 未经验证的专项经验，不得直接升级为全局规则。
4. 通用规则可以被各项目引用，但项目可以根据实际情况补充自己的专项约束。
5. 发现通用规则与实际项目冲突时，应记录冲突、适用条件和处理结果。

目的：逐步建立统一的 AI 开发经验体系，而不是让每个项目重复踩坑。

## 三、与现有 2+1 返工止损机制的关系

建议保留现有机制，并明确它是所有 AI 协作项目都应遵守的通用原则，而不只是 AIEO 的专项规定。

具体要求：

- 第一次失败：正常分析和排查。
- 第二次失败：必须重新分析根因，不能简单重复之前的方案。
- 第三次仍然失败：停止盲目修复，形成完整交接报告，交给其他 AI 独立分析。
- 同一根因不能因为更换会话、Agent 或任务名称而重置失败次数。
- 架构、安全、公共契约、数据丢失、重复执行等重大风险可以提前升级，不必等到第三次。

交接报告至少包含：问题现象、已尝试方案、失败证据、根因判断、未解决事项和下一步建议。

特别强调：不要为了维护某个 AI 的面子而无限返工。AI 应当承认能力边界，必要时主动建议切换 GPT、Codex、Kimi 或其他工具。

## 四、实施要求

本次不建议为了文档完善而中断正常开发。

请按以下方式处理：

1. 先检查现有文档结构，确认四项机制分别适合放在哪个章节。
2. 提出最小修改方案，不要大规模重写原有经验。
3. 保留现有 L-001 至 L-012 的内容和历史记录。
4. 对新增内容标注适用范围、有效性状态。
5. 不得把未经验证的判断写成已经验证的经验。
6. 更新后进行一次文档自检，检查标签是否一致、规则是否冲突、是否存在重复或过度泛化。
7. 提交 Git Commit，并提供修改摘要和 Commit SHA。

## 五、最终目标

逐步建立两层经验体系：

- **通用层：** 所有 AI 开发项目共同遵守的原则和协作规则。
- **项目层：** AIEO、Java 项目、Python 项目及其他具体项目的专项经验。

让 AI 在每次开发前能够参考历史经验，在返工时能够识别重复问题，在能力受限时能够主动止损和切换工具，在任务完成后能够沉淀可复用经验。

本次优化以小步迭代为原则，不追求一次性完美，不影响 Phase 1 正常开发。
