# AIEO 使用期问题登记（USAGE-ISSUE-REGISTER）

**版本：** v0.1【2026-11-14 会务评估会决议设立（DEC-026），用户拍板批准机制】
**定位：** AIEO 受控试运行期间的**日常使用问题统一登记处**——使用中发现的故障、异常、体验与业务问题在此如实记录，按"修复或规避"处置（DEC-025 方针）。技术假设与系统性风险仍归 `docs/FEASIBILITY-REGISTER.md`，两册互相引用、不混用。
**纪律：** 只登记真实发生的问题，不预测、不凑数；**有临时规避方案不等于已修复**；问题记录不删不改（追加更正注记）；每批真实任务结束做一次问题复盘，避免逐小问题无边界立项。

---

## 1. 问题分级与处理要求

| 级别 | 定义 | 处理要求 |
|---|---|---|
| P0 | 数据损坏、错误提交、越权、不可恢复安全事故 | 立即停止相关流程 |
| P1 | 十步核心链路中断、错误验收、错误任务归属 | 暂停受影响任务，优先修复 |
| P2 | 特定复杂场景失败，有人工替代方案 | 登记，安排修复或规避 |
| P3 | 操作体验、效率、界面、非关键功能问题 | 累积后统一优化 |

## 2. 问题条目固定字段

Issue ID（唯一编号 U-<date>-<seq>）／发现时间／关联任务（Task/Batch/Execution ID）／发生步骤（十步中具体步骤）／预期行为／实际行为／复现条件（稳定复现、偶发、未复现）／证据（日志、Commit、Correlation ID）／严重等级（P0-P3）／临时规避／根因（已确认或待调查）／处理方案（修复、规避、接受风险——接受须附依据）／状态（OPEN / INVESTIGATING / DEFERRED / FIXED / VERIFIED / CLOSED）。

## 3. 处置流程

使用 AIEO 执行真实任务 → 发现异常**立即登记** → 判断影响与严重等级 → P0/P1：暂停受影响流程、修复并重新验证；P2/P3：记录临时方案、继续受控使用 → 修复/规避/有依据接受风险 → 回归验证、更新记录、关闭问题。

## 4. 三条固定规则（不得豁免）

1. 不允许因为问题有临时规避方案，就把问题登记为已修复；
2. 不允许因为问题暂时不影响使用，就删除或隐藏问题记录；
3. 每次修复必须有对应 Commit、测试证据和复核结果。
