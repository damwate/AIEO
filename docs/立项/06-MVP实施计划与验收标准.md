# AIEO MVP 实施计划与验收标准

**版本：** v0.1  
**前置条件：** Phase 0 已通过或形成明确可接受的替代方案。

## 1. 实施原则

- 每个 Phase 都有独立目标、交付物和验收标准；
- 不跳过 GPT 规划、架构审查、代码审查和测试验收；
- 每项开发任务有 Task ID；
- 智谱必须在任务分支开发；
- GPT 审查绑定具体 Commit SHA；
- 未验收任务不能计入完成率；
- 每个阶段结束输出工程总结；
- 先实现可靠闭环，再扩展并发和分布式能力。

## 2. Phase 1：工程管理基础平台

### 功能
- 项目注册；
- Git 仓库配置；
- 需求批次；
- 任务 CRUD；
- 任务依赖；
- 状态机；
- 消息 Inbox/Outbox；
- 报告与附件；
- 操作审计；
- 基础进度看板。

### 验收
- 能创建项目和需求批次；
- 能手动创建父子任务和依赖；
- 状态转换符合状态机；
- 重复消息不会重复处理；
- 后端重启后任务状态不丢失；
- 进度只按 ACCEPTED 任务计算；
- 操作有审计记录。

## 3. Phase 2：GPT 多角色控制

### 功能
- GPT-01 至 GPT-05 角色配置；
- 会话 URL 管理；
- 专用 Chrome Profile；
- 浏览器 Worker；
- 任务包发送；
- 回复提取；
- JSON Schema 校验；
- 登录失效和安全验证人工接管；
- 会话并发限制。

### 验收
- 五个角色可以分别定位；
- 消息不会串会话；
- 回复关联正确的任务；
- 生成中不提前提取；
- 页面异常能暂停；
- 浏览器重启后能恢复或明确标记待人工检查；
- 不能将网页自动化失败伪装为 GPT 完成。

## 4. Phase 3：ZCode 自动开发接入

### 功能
- AIEO MCP Server；
- ZCode MCP 配置；
- 任务上下文读取；
- 开发进度回报；
- 开发报告提交；
- ZCode 任务触发适配器；
- Git Worker；
- 测试结果收集。

### 验收
- ZCode 只能领取 READY 且依赖满足的任务；
- 任务报告关联正确 Task ID 和 Execution ID；
- Git Commit 可独立验证；
- 测试结果有日志证据；
- 无法启动 ZCode 时明确暂停并通知；
- 任务重复派发有防护。

## 5. Phase 4：端到端闭环

### 完整流程
需求 → GPT 规划 → GPT 架构审核 → 任务调度 → 智谱开发 → Git 提交 → GPT 代码审查 → GPT 测试验收 → GPT 总审计 → 进度报告。

### 验收
- 至少一个真实但低风险的项目需求完整跑通；
- 至少一次有记录的返工；
- 返工后重新审查；
- 所有结论绑定实际 Commit；
- 任务、消息、报告和日志可追溯；
- 用户可以暂停、恢复和取消；
- 人工审批边界有效。

## 6. Phase 5：并发与多项目

只有单任务闭环稳定后才启动。

### 功能
- 多项目看板；
- 任务优先级；
- Worker 能力注册；
- 多执行器调度；
- Git Worktree；
- 并发冲突检测；
- PostgreSQL；
- Redis；
- 局域网 Worker；
- 节点认证和访问控制。

### 验收
- Worker 离线后任务可恢复；
- 同一任务不会被两个 Worker 同时执行；
- 不同任务不会误写同一工作目录；
- 网络断开后消息可补偿；
- 多节点日志和审计统一；
- 权限只能访问授权项目。

## 7. MVP 最终验收清单

### 需求与规划
- [ ] 用户可提交需求；
- [ ] GPT-01 输出结构化任务计划；
- [ ] GPT-02 完成架构审核；
- [ ] 任务依赖经过校验。

### 开发执行
- [ ] 智谱能接收指定任务；
- [ ] 任务包包含工程规范和验收条件；
- [ ] 开发进度可追踪；
- [ ] 阻塞可上报；
- [ ] 开发报告结构化。

### Git 与测试
- [ ] 独立任务分支；
- [ ] Commit SHA 可验证；
- [ ] Diff 可读取；
- [ ] 测试日志可追溯；
- [ ] 工作区状态可验证。

### 审查与验收
- [ ] GPT-03 审查真实 Diff；
- [ ] GPT-04 检查真实测试证据；
- [ ] REWORK 能创建返工；
- [ ] 新 Commit 触发重新审查；
- [ ] GPT-05 输出批次审计。

### 系统可靠性
- [ ] 消息去重；
- [ ] 超时处理；
- [ ] 失败重试；
- [ ] 人工暂停；
- [ ] 重启恢复；
- [ ] 操作审计；
- [ ] 敏感信息保护。

## 8. 明确不纳入 MVP

- 自动生产部署；
- 自动合并主分支；
- 自动修改生产数据库；
- 多电脑分布式调度；
- 任意模型自动切换；
- 未经验证的网页私有接口；
- 无人工边界的无限自动返工。

## 9. 项目成功标准

AIEO MVP 的成功不是“AI 能自动写代码”，而是：

1. 需求能够被拆解成可验收任务；
2. 开发任务能够被可靠派发；
3. 开发结果能够在 Git 中定位；
4. 审查和测试有真实证据；
5. 不通过能够返工；
6. 进度能够由系统准确计算；
7. 人工能够随时介入；
8. 全过程能够追溯和复现。
