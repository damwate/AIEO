# AIEO 立项设计包

**项目名称：** AI Engineering Orchestrator（AIEO，AI 软件工程协同管理系统）  
**文档版本：** v0.1  
**状态：** 立项设计 / Phase 0 技术验证前  
**部署基线：** Windows 单机优先，未来支持局域网多执行节点

## 1. 本设计包包含什么

| 文件 | 用途 |
|---|---|
| `01-总体架构设计.md` | 系统定位、总体架构、模块边界、技术选型 |
| `02-GPT角色与会话规范.md` | 五个 GPT 网页会话的职责、输入输出与提示词约束 |
| `03-任务消息与报告协议.md` | GPT、ZCode、调度器之间的消息协议和示例 |
| `04-任务状态机数据库与Git规范.md` | 状态流转、数据模型、分支与审查规则 |
| `05-Phase0技术验证与今晚开工任务.md` | 智谱今晚应先做的技术验证，不直接开发完整平台 |
| `06-MVP实施计划与验收标准.md` | Phase 0 之后的分阶段实施路线及验收门槛 |

## 2. 当前已确定的前提

- ZCode 桌面软件运行在 Windows。
- 网页 GPT 使用 Windows Chrome，多个独立聊天标签页/会话。
- 自动化目标为尽可能全自动，异常时人工介入。
- 第一阶段尽量在一台 Windows 电脑上运行。
- 未来任务量或资源需求增加时，再扩展到局域网多电脑。
- 网页 GPT 负责规划、架构审查、代码审查、测试验收和汇总。
- ZCode/智谱负责具体开发、测试执行、开发报告和 Git 提交。
- Git 是代码交付证据；工程管理系统是任务状态和报告的唯一事实来源。
- 七大软件工程规范作为统一质量基线：需求分析、架构设计、开发实施、代码质量、测试验收、项目收尾、Git 提交与版本管理。

## 3. 当前不能假定已经成立的技术能力

以下事项必须通过 Phase 0 实测，不能只根据产品宣传或 MCP 支持声明推断：

1. AIEO 能否从外部可靠地创建/启动一个新的 ZCode 开发任务。
2. ZCode MCP Server 是否能在当前安装版本中被智谱 Agent 正常调用。
3. ZCode 是否能在任务执行期间主动回调 AIEO，还是只能在 Agent 主动调用 MCP 时汇报。
4. Playwright 是否能在用户授权登录后，稳定定位指定 GPT 会话、发送消息并读取完整回复。
5. Chrome/ChatGPT 的登录验证、验证码、安全检查或页面变化出现时，能否安全暂停并由人工接管。

**原则：** Phase 0 先验证技术边界，再决定最终实现。不要把未验证的能力写成已完成的系统功能。

## 4. 今晚开工建议

今晚只启动 `05-Phase0技术验证与今晚开工任务.md` 中的任务。不要直接生成完整 Vue + FastAPI + 数据库平台，也不要先搭建复杂 Redis/PostgreSQL 集群。

今晚目标是拿到：
- 环境盘点结果；
- ZCode MCP 接入验证；
- ZCode 外部启动能力验证；
- GPT 浏览器收发消息最小验证；
- Git 自动采集最小验证；
- 风险与最终技术路线建议。

Phase 0 通过后，再按 `06-MVP实施计划与验收标准.md` 逐阶段开发。
