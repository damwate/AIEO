# AIEO 可行性风险与未验证假设登记（FEASIBILITY-REGISTER）

**版本：** v0.2【草案——待用户 2026-11-14 10:30 审阅】
**定位：** 项目全部未验证技术假设与可行性风险的单一登记处（EXP-PLANNING-001 §五）；每会话发现新问题**先登记、评估，不得无边界扩展当前任务**（§二.5）。
**纪律：** 每项必须含假设内容、当前证据、缺口、风险等级、验证路径与状态；关闭一项须附证据并记版本；"已验证假设区"保留成果防止重复开发（§八）。
**初始化依据：** 复盘盘点 `docs/reviews/2026-11-14-总体规划与可行性复盘-主会话盘点.md` 议题 2/5/6；DEC-017/DEC-021 边界。

**风险等级定义：** 高=直接威胁十步闭环目标或项目命门；中=影响 MVP 验收完整度或效率；低=局部影响。
**状态定义：** OPEN=未验证待验证路径；OPEN-DEFERRED=已裁定暂缓（有明确恢复条件）；VERIFIED=已验证（附证据）；INVALIDATED=被证伪（附原因与决策）。

## 1. 未验证假设（OPEN）

### F-001 中央调度引擎未工程化
- **假设/现状：** 立项架构图最核心的 CORE 节点（需求→批次→拆解→派单→监控→状态机推进）没有模块归属、没有实现条目、没有排期；当前=人工+主会话工具（`phase0/tools/gpt_dispatch.mjs` 手动派单）。
- **当前证据：** 盘点议题 2（2026-11-14 实查）；`docs/phase1/module-boundaries.md` 四模块职责中无调度引擎条目。
- **风险：** 高——MVP"任务能够被可靠派发"（06 §9-2）的承载者缺位；D1′ 前可由人工+主会话顶替，Phase 4 多角色前必须工程化。
- **验证路径：** D1′ 以最小形态人工编排走通全链并记录派单动作清单 → Phase 4 前立项工程化任务（归属 M1 或独立模块，届时拍板）。
- **状态：** OPEN

### F-002 真实网页 GPT 多角色收发（全项目命门前提）
- **假设：** "网页自动化能否稳定支撑真实开发闭环"。
- **当前证据：** Phase 0 POC 单点证据（单 unit、稳定 DOM、公开仓库，DEC-017 允许范围；gpt_roundtrip + 真实派单提取）；M2 实现完整（28 源码文件）但验收为**浏览器模拟级**（`phase1/logs/m2-gpt-controller-20261113/browser_simulation-*`）。
- **缺口：** 真实 chatgpt.com 多角色（GPT-01 规划/GPT-03 审查等）多轮收发从未进入业务链。
- **风险：** 高——十步闭环 5 个节点依赖此腿；模拟级证据不构成真实链路验收（🔶 CLAIMED_ONLY 边界）。
- **验证路径：** D1′ 真实规划会话（DEC-017 边界内：公开仓库/单 unit/稳定 DOM/fail-closed）→ Phase 4 逐角色扩展；扩展场景（多 assistant unit/动态裁切恢复等）随 T-P1-906 分批复审。
- **状态：** OPEN

### F-003 测试执行 Worker 缺位
- **假设/现状：** 立项架构有 TEST 节点；M1 只做 test_reports **登记**，测试的真实执行与日志证据采集无人负责。
- **当前证据：** 盘点议题 2；PHASE-STATUS §2.3"测试日志可追溯 ❌"。
- **风险：** 高——"审查和测试有真实证据"（06 §9-4）的测试半边缺位；GPT-04 检查真实测试证据（§7）被其牵制。
- **验证路径：** D1′ 通过后立项最小测试执行 Worker（真实执行+日志采集+登记），归属 M4 或独立，届时拍板。
- **状态：** OPEN

### F-004 D1′ 真实端到端垂直切片可行性
- **假设：** 一条真实低风险需求能走完最小闭环：M1 REST 建项目/批次/任务 → 真实 ChatGPT 规划会话 → 回复经 M1 REST 登记 → 状态机推进 → ZCode 经 MCP 领取 → 真实代码提交 → M4 采集 → 报告登记。
- **当前证据：** 无全链真实证据（集成套件 GPT/ZCode 腿为夹具）；各段能力有分段证据（M1 REST 43 用例绿、MCP POC、M4 真实 commit 采集）。
- **风险：** 高——本项即 P0-B 验证器本身；若失败触发 REPLAN（复评五态）。
- **验证路径：** 任务定义遵守 DEC-017（公开仓库/单 unit/稳定 DOM/任何不确定 fail-closed）；任务号段已会务裁定 T-P1-905（方案 A，2026-11-14，依赖 T-P1-904 先行，任务书 `docs/phase1/D1PRIME-VERTICAL-SLICE-BRIEF.md`）。
- **状态：** OPEN

### F-005 管理后台仅雏形
- **假设/现状：** `app/frontend` 仅 5 个源码文件；MVP 要求"基础进度看板"（06 §2），M1 board API 已实现，前端未承载。
- **风险：** 中——MVP §7"进度能够由系统准确计算"有 API 层证据，用户可视界面缺位；不阻塞 D1′。
- **验证路径：** 暂缓（盘点议题 6 裁定）；D1′ 期间可临时以 M1 REST/board API + 日志人工核对；Phase 4 前补最小看板页。
- **状态：** OPEN-DEFERRED

### F-006 BLOCKED-1 扩展场景（六项逐项待验收）
- **假设：** 真实 ChatGPT 多 assistant unit、真实动态虚拟列表裁切恢复、私有仓库权限、真实网络故障注入与退避耗尽、多文件部分读取失败、M1 REST/数据库/ACK 与完整平台并发——均未验收。
- **当前证据：** DEC-017 核心路径 PASS_WITH_CONSTRAINTS（允许开工，扩展场景不解除）；§2.6 生效（DEC-021）不改变扩展场景边界。
- **风险：** 中——Phase 4 多角色长会话将逐步撞上；fail-closed 纪律保证不污染业务链。
- **验证路径：** T-P1-906 C2 分批复审、逐项解除（DEC-018 路线）；每项需可复现证据绑定 commit 经独立审查。
- **状态：** OPEN

### F-007 契约体系消费者缺位
- **假设：** 消息信封/报告/C3 错误码等 Schema（缩编前计划 130+ 文件）的真实消费者在 D1′ 之前不存在——M2/M3/M4 至今未通过 M1 REST 互通过一单真实消息。
- **当前证据：** 盘点议题 4；现有 Ajv 37/37 仅覆盖 `contracts/v1.0/` 现有 4 Schema；C3 已在 M1 错误边界落地（`app/platform/errors.py` 与契约 §4.2 一致）。
- **风险：** 中——方向正确、节奏超前；继续无消费者建设将复演"先细节后前提"。
- **验证路径：** T-P1-904 缩编为 D1′ 消费子集（15-20 文件）+ PENDING 矩阵，其余随消费者增量；D1′ 为第一个真实消费者。
- **状态：** OPEN
