- **依据：** FEASIBILITY-REGISTER F-003——立项架构有 TEST 节点，M1 只做 test_reports 登记，测试的真实执行与日志证据采集无人负责；06 §9-4"审查和测试有真实证据"的测试半边缺位。
- **前置已满足：** T-P1-905 D1′ 已通过独立验收并合并 main（DEC-027，merge `9ce7872`+`91b11df`，main=6787444）。
- **定位：** 最小可用测试执行 Worker——单 Python 环境，对指定 worktree/commit 真实执行测试命令清单，采集日志证据，产出符合冻结 `test-report.schema.json` 的结构化报告；失败如实登记，不粉饰。
- **归属（F-003 留待拍板项）：** 建议**独立 CLI worker**（`phase1/tools/test_worker.py`），不并入 M4——M4 职责为 git 采集应保持单一；与 M1/调度的集成后置 F-001 阶段。
- **执行形态：** 主会话 ZCode 腿真实开发 + ChatGPT 腿真实规划收发（D1′ 先例，不冒充独立 CLI 会话）。

## 2. 范围：最小闭环七步（草案，会务评审可调）

- **S1** 本任务书会务评审→定稿（号段、归属、REST 取舍三项拍板）→用户开工授权。
- **S2** Worker 实现：单 Python 标准库（无第三方依赖）；输入=worktree 路径+命令清单（文件或参数）；逐命令真实 subprocess 执行，超时/异常 fail-closed。
- **S3** 正向真实执行演示：对 D1′ 开发产物（`bundle_gate.mjs --help` 用法回归 + 夹具 parts 14/14/tar/unpack）执行，exit=0 证据落盘。
- **S4** 失败如实演示：执行一条已知非零退出命令（如 bundle_gate 非法参数），报告如实记 fail，不重试不粉饰。
- **S5** 证据采集：stdout/stderr/exit code/耗时逐命令落盘 `phase1/logs/t-p1-907-<ts>/`，原始字节保留，登记 SHA-256。
- **S6** 结构化报告：报告 JSON 按 `contracts/v1.0/test-report.schema.json`（required: task_id/execution_id/commit_sha/execution_result/result），Ajv 校验通过。
- **S7** 提交与验收：开发分支/证据分支分离提交（905 先例，base=合并后 main），提交独立验收（另行，不因开工获得合并/发布权限）。
- **REST 登记取舍（会务拍板）：** 方案 A=最小版含 M1 REST 登记（POST test-report，复用 runtime service token，fail-closed）；方案 B（建议）=最小版只出报告文件，REST 自动登记留 F-001 集成阶段，理由：DEC-026 最小版口径为"真实执行+日志采集+结构化报告"，登记端点消费属调度集成面。
