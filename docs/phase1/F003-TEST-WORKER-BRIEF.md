## 1. 目标与定位

- **依据：** DEC-026 决议二路线（905 验收→F-003→F-001→多角色→906 顺延）；06 §10.3 独立任务行；FEASIBILITY-REGISTER F-003（M1 只做 test_reports 登记，真实执行与日志采集无人负责）。
- **前置已满足：** T-P1-905 已通过独立验收并合并 main（DEC-027）。
- **定位：** 最小可用测试执行 Worker——单 Python 标准库（无第三方依赖），对指定 worktree/commit 真实执行测试命令清单，采集原始日志证据，产出符合冻结 `test-report.schema.json` 的结构化报告。
- **设计原则（会务判断，作为本任务最高设计约束）：** Worker 只负责提供事实，不负责宣布事实是否可信——Worker 真实执行、保存原始证据、生成结构化报告；Schema 检查报告结构；独立审查者判断证据是否足以支持验收；用户最终授权。禁止"自己执行、自己判断、自己宣布 PASS"的闭环漏洞。**Worker 运行成功 ≠ 被测项目测试通过。**
- **归属（拍板）：** 独立 CLI Worker `phase1/tools/test_worker.py`，不并入 M4（M4 保持 git 采集职责单一）；不引入常驻服务/消息队列；独立 CLI 便于后续 F-001 调度调用。**独立 CLI ≠ 独立调度系统**——本阶段只执行一个明确的测试任务，不管理多任务。
- **执行形态：** 主会话 ZCode 腿真实开发 + ChatGPT 腿真实规划收发（D1′ 先例，不冒充独立 CLI 会话）。

- **S4** 失败真实演示：执行一条已知非零退出命令。**必须证明 Worker 能正确识别该失败并写入报告**（不只是证明被测程序有错误处理能力，而是证明 Worker 有失败采集能力）。

## 3. 硬边界（全部沿用，不解除）

1. **DEC-017 扩展场景限制不解除**；DEC-023（906 前置）不变；冻结契约文本不修改（test-report schema 只消费）。
2. **C6 秘密不进 Git**；脱敏与归档要求见 §7（F-06）。
3. **出站 ≤1200 UTF-8 字节**；审查/咨询一律 `--new-session`+自包含简报；只按完整 40 位 SHA 读仓库；回复信任以 reply.txt 原始字节+SHA 为准；600s 超时 env。
4. **零 mock 红线：** 测试必须真实执行；不能用伪造 subprocess 返回值代替真实进程、不能用人工编写的成功报告代替 Worker 产物、不能用预先生成的日志冒充本次执行证据；任何模拟替代则整体不得 PASS。
5. **历史不重写**；PASS≠授权／归档≠定稿；下一任务不继承上一任务额外权限。
6. **不修改 M1 代码；不扩展 M4 测试执行职责；不提前实现 F-001（调度/批次/REST 集成）；不提前开放 GPT-04 审查消费链路**；合并发布必须另行取得授权。
7. **范围零扩张：** 不实现调度/批次/并发/多环境/自动重试策略（F-001 范围）。

## 4. 执行安全（会务 F-01，全部为硬要求）

- worktree 必须存在且是有效 Git 工作树；指定 commit 必须是完整 40 位 SHA；Worker 必须核对 worktree 实际 HEAD 与指定 commit 一致，不一致即失败退出。
- **命令清单必须非空；空清单直接拒绝执行，不得产生 EXECUTED_PASS 或 PASS**（零条命令、零测试不得生成成功报告）。
- 命令使用 argv 数组执行，**禁止 shell=True**；禁止命令清单通过任意 shell 字符串执行——不能让 Worker 变成不受限制的任意命令执行入口。
- 每条命令固定工作目录（=指定 worktree），不得自行改变 Worker 执行根目录。
- 超时、命令不存在、进程启动异常均产生明确失败结果，不得伪装为成功。

## 5. 结果语义两层映射（会务 F-02 终版，五行穷举）

| 执行事实 | `execution_result`（执行事实） | `result`（任务验收结论） |
|---|---|---|
| 所有命令执行成功 | EXECUTED_PASS | PASS |
| 命令非零退出、单条命令启动异常或超时 | EXECUTED_FAIL | REWORK |
| Worker 自身无法启动或任务级执行被阻断 | BLOCKED | BLOCKED |
| 未执行任何命令（协议兼容状态，本 Worker 不主动生成） | NOT_EXECUTED | BLOCKED |
| CLAIMED_ONLY 声明 | CLAIMED_ONLY | BLOCKED |

允许值以冻结 Schema 为准（execution_result 五种枚举 EXECUTED_PASS/EXECUTED_FAIL/NOT_EXECUTED/CLAIMED_ONLY/BLOCKED 全列；result: PASS/REWORK/BLOCKED）。**以上五行映射为穷举映射，所有情况均有确定结果，不留下人工解释空间；整体状态由实际执行结果计算，不允许人工覆盖。F-003 Worker 不得自行生成 CLAIMED_ONLY——本任务要求真实执行。**

**边界定义（与 §4/§10 一致的机器执行语义）：** 命令级启动异常 ≠ Worker 启动失败；单条命令失败不阻断后续命令；Worker 自身无法启动、输入校验失败或任务级阻断属于 BLOCKED；超时属于命令执行失败，整体 EXECUTED_FAIL；空命令清单属于输入校验失败，不得产生成功报告。

**NOT_EXECUTED 适用限定（v0.5，消除与 BLOCKED 的交叉）：** F-003 最小版不支持外部取消语义（范围零扩张）——**NOT_EXECUTED 为协议兼容状态，本 Worker 不主动生成**。只要输入校验通过且 Worker 正常启动，执行即进入命令执行阶段，终态只能是 EXECUTED_PASS/EXECUTED_FAIL/BLOCKED 之一；输入校验未通过（空清单、无效 worktree、非完整 40 位 SHA、HEAD 不一致）一律 BLOCKED，不落入 NOT_EXECUTED。

## 6. 日志证据与报告互相对应（会务 F-03）

- 每条命令产生三件套：`command-NNN.stdout` / `command-NNN.stderr` / `command-NNN.meta.json`（命令及参数、开始/结束时间、耗时、退出码、stdout SHA-256、stderr SHA-256、超时或异常状态）。
- **原始日志保留字节**，不允许只保存格式化的终端输出。
- 报告 payload 保存对应日志的相对路径及 SHA-256，审查者可从报告追溯到原始证据。

## 7. 脱敏与归档（会务 F-06）

- 沿用 905 R1-R5 脱敏扫描方法；归档日志与报告之前必须扫描。
- **原始日志不得因脱敏被静默篡改**；发现秘密时阻断归档，保留本地受保护证据并如实登记。
- 日志 SHA-256 必须对应实际归档的字节；**扫描 CLEAN ≠ 执行证据真实——二者是两个不同验收条件**。

## 8. 报告与 Schema 校验（会务 F-05）

- `contracts/v1.0/test-report.schema.json`（Blob SHA `1bda905c…`，required: task_id/execution_id/commit_sha/execution_result/result）只消费不修改；**Schema 校验失败时整体不得 PASS**。
- execution_id 唯一且符合 EXEC-数字 格式；commit_sha 必须与实际执行对象一致；payload 包含命令执行明细和证据索引。
- Ajv 校验使用仓库现有可复现环境（T-P1-904 交付的 Ajv 141/141 环境），不引入未经批准的新依赖。

## 9. REST 与凭据边界（拍板方案 B）

- 本阶段只生成报告文件，**不做 M1 REST 自动登记**（留 F-001 集成阶段）；方案 B 不意味着报告不能被后续消费，而是本阶段不负责自动登记。
- **Worker 默认不需要业务凭据**：F-003 不需要 M1 service token；运行目录使用 F-003 专用 gitignored 目录（如 `runtime/t-p1-907-<ts>/`），不引入不必要的秘密。

## 10. 失败处理策略（会务 F-04，实现前明确；两类失败区分）

顺序执行；不自动重试；记录每条命令真实结果；整体状态按实际执行结果计算，不允许人工覆盖；**状态映射以 §5 五行穷举表为准**。两类失败明确区分：

- **单条命令启动异常：** 记录该命令失败，**继续执行剩余命令**（不因一条命令启动异常丢失后续命令的执行事实），整体按 EXECUTED_FAIL 处理。
- **Worker 自身无法启动、输入校验失败或整个执行任务被阻断：** 整体 BLOCKED。
- **超时：** 记录对应命令超时，继续后续命令，不自动重试；超时不得记录成普通成功。

## 11. 验收标准（八项，会务终版）

| # | 要求 | 必须提供的证据 |
|---|---|---|
| A1 | 真实仓库、真实 commit 执行 | 完整 40 位 SHA、HEAD 核验 |
| A2 | 正向测试真实通过 | 真实进程、退出码 0、原始日志 |
| A3 | 失败测试真实发生 | 非零退出码、失败报告 |
| A4 | Worker 异常处理正确 | 超时、启动异常等 fail-closed 证据 |
| A5 | 日志证据完整 | 原始字节、逐项 SHA-256 |
| A6 | 报告符合冻结契约 | Ajv 校验结果、报告与日志关联 |
| A7 | 安全和权限边界符合要求 | R1-R5 CLEAN、无秘密进入 Git |
| A8 | 工程交付完整 | 双分支、RUN-RECORD、独立验收、范围核对 |
