## 1. 使用规则

1. **每次会话轮换前**必须生成本交接包并提交到仓库（GPT 建议 3）；轮换在任务可暂停、有明确交接点时执行；
2. 新会话**先核对实际仓库状态**（git status / git log / 文件存在性），再以交接包作为上下文起点——交接包内容若与仓库实际不符，以仓库为准并立即修正交接包；
3. **三区制度（GPT 建议 4）：**
   - **事实**：必须附证据（commit SHA、文件路径、测试结果）；
   - **决策**：必须注明版本与出处（谁决策、哪份文件哪个 commit）；
   - **待确认**：不得写成事实；新会话不得将待确认事项当作既定前提；
4. 避免只复制聊天摘要——每条内容都要能回溯到仓库里的证据；
5. 交接包命名建议：`handoff/<目标阶段>-HANDOFF.md`（本次实例：`D:\AIEO\handoff\PHASE1-HANDOFF.md`）。

## 2. 模板

```markdown
# 会话交接包：<源阶段/会话> → <目标阶段/会话>

**生成时间：** <日期时间>  **生成者：** <会话角色>
**性质：** 事实（附证据）／决策（注明版本）／待确认（不得当事实）——逐条标注

## 1. 目标与阶段
<项目一句话目标；当前所处阶段；本次交接的目的>

## 2. 仓库与基线（事实）
- 仓库：<remote URL>
- 分支：<分支名>
- 基线 commit：<git rev-parse HEAD 实查的 40 位 SHA>（注明与文档记录的差异，如有）
- 工作区状态：<git status --porcelain 实查结果；clean 或列出未提交项>
- 与远端同步状态：<git status -sb 的 ahead/behind>

## 3. 已完成事项（事实，逐条附证据路径/commit）
<编号列出；每条注明证据：报告文件、commit SHA、日志路径>

## 4. 未完成事项（事实）
<编号列出；注明是"全部未开始"还是"部分完成及断点位置">

## 5. 架构决策（决策，注明版本与出处）
<编号列出；每条格式：决策内容 + 版本/出处（文件路径、commit SHA）+ 日期；
详表引用 decision-log.md 时此处只列决策标题>

## 6. 模块契约（决策）
<当前生效的契约文件与版本；是否已定稿；变更申请入口>

## 7. 测试环境与已知约束（事实）
<OS/运行时/依赖版本；网络/代理等环境约束；来源报告>

## 8. 历史审查结论（事实）
<轮次表：轮次/commit/结论/核心问题；原始证据目录>

## 9. 已知风险（事实 + 待确认混合时分开标注）
<每条注明来源（报告章节）与缓解措施；未验证事项如实列出>

## 10. 测试命令与结果（事实）
<关键测试的命令与最近一次结果、证据文件路径>

## 11. 下一步（计划）
<编号列出，注明顺序与进入条件>

## 12. 禁止事项（决策）
<红线清单，引用 agent-contract.md §6；交接双方共同遵守>

## 13. 待确认事项（待确认——不得当事实）
<列出悬而未决项、决策人、决策所需信息>
```
