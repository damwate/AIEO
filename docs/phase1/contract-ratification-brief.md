## 二、契约决策摘要（整体设计与批准范围）

1. **定位：** 本契约是 Phase 1 四模块（M1 平台基座 / M2 GPT 控制器 / M3 ZCode Bridge / M4 Git Worker）的公共契约，v1.0.0 于 2026-11-12 冻结，来源为 GPT 契约讨论产出（17 项 gaps 全部闭合，附录 A）+ 立项文档 03-协议/04-规范 + module-boundaries v0.1（冻结基线 `555fd44`）。
2. **八项契约：** C1 API 协议、C2 数据模型、C3 错误码、C4 日志、C5 分支策略、C6 配置、C7 认证授权、C8 版本兼容——均为"全量采纳 GPT 方案/清单"的定稿口径（C3 明确 27 条而非沟通中的 28 条口径误差）。
3. **关键架构决策（已实现验证）：** 127.0.0.1 单机单用户（禁 0.0.0.0）；Argon2id；16 张表全禁物理删除、返工 append-only；状态机由 M1 唯一持有、Agent 只能提交事件；Outbox 同事务登记 + 幂等去重；audit_logs 永久保留与业务同事务；跨模块只经 M1 服务接口协作；Git 不参与数据库事务（§11.4 五步流程）。
4. **责任边界定稿（§11）：** 共享 ORM 归 M1、迁移脚本归 M1、锁服务独立组件由 M1 提供全部模块使用（DEC-001 OS 句柄）、共享文件修改权归主会话。
5. **遗留显式标注：** BLOCKED-1（§12）与 6 项开放问题（§13）未静默冻结——"未定稿条目必须标 BLOCKED"本身就是本契约的治理决策（gap 17）。

## 三、C1~C8 分项审阅卡

每卡给出：核心条款（要点）→ 追认关注点 → 建议结论。审阅时按需对照契约原文节号。

### C1 API 协议（§2）

- **核心条款：** 仅绑 127.0.0.1；前缀 `/api/v1/`；REST 端点表 32 条逐条冻结（含幂等规则）；消息信封 11 字段类型/长度/必填规则；`POST /messages` 同事务登记 + `message_id` 主键去重；Outbox 状态机 PENDING→SENT→ACKED / RETRYING→DEAD_LETTER（仅人工 /requeue）；ACK 超时≠任务失败；未知字段忽略的兼容规则。
- **§2.6 GitPointer 双向 payload（BLOCKED-1 修订稿）：** 出站网页消息 ≤1200 UTF-8 字节硬上限（超限不发送/不截断/不拆分）；入站不受 1200 限制、按结构化 unit 完整提取+哈希持久化；统一 manifest Schema；输入材料 commit 与 `reviewed_commit` 分离；权限/秘密禁入/永久保留规则；统一失败边界表（禁止自动降级换源）。
- **关注点：** §2.6 标注"修订中，待复审"（DEC-012）——建议**附条件批准**：C1 整体批准，§2.6 以 DEC-012 复审 PASS 为生效条件，复审前按现行约束运行。
- **建议结论：** 批准（§2.6 附条件）。

### C2 数据模型（§3）

- **核心条款：** 16 张核心表逐表字段/约束/索引冻结；业务 ID 格式表（T-P1-<序号> 等 10 类）；全业务表禁止物理删除；返工历史 append-only（`UNIQUE(task_id, attempt)`，新 execution 不覆盖旧行）；状态机 14 态由 M1 唯一持有；BLOCKED/CANCELLED 必须带原因/责任方/解除条件（CHECK 约束强制）；SQLite 但业务逻辑不得依赖其特有行为。
- **关注点：** 无需用户额外拍板的实现细节均已定稿；迁移工具（Alembic 或等效）留 M1 实现期选型（§13-5）。
- **建议结论：** 批准。

### C3 错误码（§4）

- **核心条款：** 九组 27 条编号表全量采纳（SYS 3/REQ 3/AUTH 3/RES 3/TASK 3/MSG 2/PROVIDER 5/GIT 3/ART 2）；统一错误 Schema（code/message/details/retryable/correlation_id 必填）；HTTP 状态一一映射；禁止透出堆栈；编号禁止复用。
- **建议结论：** 批准。

### C4 日志规范（§5）

- **核心条款：** 27 字段必填/可选分级清单；NDJSON 单行 JSON；落盘 `logs/phase1/<service>/` 按配置（禁硬编码绝对路径）；运行日志 30 天轮转、audit_logs 永久保留；审计与业务状态变更同事务（或可靠 Outbox）；敏感字段脱敏（凭证不落日志，只记类型/摘要）。
- **建议结论：** 批准。

### C5 分支策略（§6）

- **核心条款：** 任务 ID `T-P1-<序号>`；分支 `feature|fix/<TASK-ID>-<short-name>`（正则冻结）；集成分支 `integration/phase1`；模块→集成由主会话 `--no-ff` 合并；**集成→main 仅用户人工审批后由主会话执行**；禁止已推送共享分支 rebase/force-push；提交信息规范可自动检查（5 条 pre-commit 规则）。
- **关注点：** 本项直接约束即将进行的 B（main 合并）——合并授权必须走 approvals 流程留痕。
- **建议结论：** 批准。

### C6 配置命名（§7）

- **核心条款：** `AIEO_` 前缀（模块段枚举）；env > 文件 > 默认值；14 项首期核心配置默认值冻结（含 `AIEO_SYSTEM_PROXY` 默认 127.0.0.1:10391——注意实查为准，动态端口）；秘密只经环境变量/凭据存储，配置文件仅占位符；fail-fast 启动校验。
- **建议结论：** 批准。

### C7 认证授权（§8）

- **核心条款：** 单机单用户最小方案；绑定 127.0.0.1 禁 0.0.0.0；Argon2id 口令；随机高熵 Session ID + Cookie 三属性（HttpOnly/SameSite=Lax/Secure）；CSRF 防护 + 空闲/绝对过期 + 撤销；单 OWNER 角色；MCP/CLI 独立本机服务身份（不伪装浏览器用户）；登录/轮换/敏感操作入审计；未来局域网开放需另立 HTTPS 方案（§8.8 首期不做）。
- **关注点（GPT 提示）：** Phase 1 测试通过≠生产安全验证完成；C7 属"从简但留字段"方案，若未来暴露局域网需整体验收。
- **建议结论：** 批准（附知情：首期边界为单机单用户）。

### C8 版本兼容（§9）

- **核心条款：** 应用 SemVer 与契约版本分离；主版本不兼容（新增必填/删除/改名/改类型/改语义）；主版本不匹配返回 `REQ-0003` 禁静默降级；`supported_versions` 经 health 公布；废弃需迁移窗口（默认 ≥14 天或 ≥2 批次周期）；migration version 独立只向前迁移、禁模块自行改表；历史数据按原版本保留、版本化解析器读取、不批量覆盖。
- **建议结论：** 批准。
