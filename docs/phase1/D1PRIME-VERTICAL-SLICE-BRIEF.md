## 1. 目标与定位

一条**真实低风险需求**走完最小闭环，验证"网页自动化能否稳定支撑真实开发闭环"这一全项目命门前提。D1′ 是 06 §10.2 P0-B，是 Phase 4 多角色闭环的前置验证器，也是契约体系的第一个真实消费者。

**诚实边界：** D1′ 验证的是**前提可行性**，不是工程形态——派单通道允许使用现役已验证的 `phase0/tools/gpt_dispatch.mjs`（CDP 接管，DEC-002），不要求 M2 工程化先行（工程化归 Phase 4）；调度仍可由主会话人工编排（F-001 的工程化在 D1′ 通过后立项）。

**执行形态注记（v0.3 新增，如实登记口径）：** ①ChatGPT 规划腿走真实 chatgpt.com（gpt_dispatch.mjs CDP 接管真实浏览器，非模拟页面）；②ZCode 开发腿由编排会话自身作为真实 ZCode 执行者承接——claim/progress/submit 一律经真实 M3 `bin/aieo-zcode-mcp.mjs`（stdio 子进程 + 真实 MCP 客户端驱动）打到真实 M1 REST 并落真实 DB，开发变更为真实任务分支 commit；编排者本人承接开发这一事实写入全链记录文档，不冒充"独立 CLI 会话开发"；③任何一步若实际无法走真实通道，按 §2 通则 fail-closed 登记，不得以等效模拟顶替后仍记该步 PASS。

**真实性与 fail-closed 通则（v0.3 新增，DEC-024-C ①②，适用于上表每一步）：**
1. **每步必须走真实外部资源与真实副作用**——Mock 返回值、本地伪造成功响应、仅内部函数调用、无真实外部副作用的模拟流程，一律不构成该步完成证据；外部资源暂不可用时如实记录 BLOCKED 或未验证，不得把模拟通过登记为真实端到端 PASS；
2. **每步必须 fail-closed**——外部资源不可用、请求超时、响应格式不符契约、外部执行结果无法确认、关键身份状态或关联信息缺失、无法确认操作是否已发生时，停止成功路径转入如实登记（BLOCKED/REWORK 按实态）；**尤其避免超时后盲目重试造成重复执行**（重复建任务/重复派单/重复登记/重复领取/重复 commit 采集）——登记类操作一律先查幂等键再重试，恢复只重试登记、不重跑外部执行（DEC-012/DEC-014 口径）；
3. 超时 ≠ 任务失败（§3 既有条款）；任何 fail-closed 事件本身也是有效交付证据（§5-5）。

## 3. 硬边界（DEC-017 全部适用，不解除）

- 扩展场景（多 unit/动态裁切/私有权限/故障注入）不触碰，归属 T-P1-906 分批复审；
- 不合并 main（DEC-010）；ZCode 开发在任务分支；
- 派单遵守会话锁 + 代理探活（DEC-004 口径更新 2026-11-14：系统代理当前=127.0.0.1:13772，历史 10391/6822 已过时，探活规则不变）；
- 回复信任以 reply.txt 原始字节 + SHA 为准；超时 ≠ 任务失败。

### 3.1 DEC-024-C 开工四约束（2026-11-14 用户拍板，会务决议全文登记，v0.3 新增）

①**必须真实外部资源**——Mock 返回值/本地伪造成功响应/仅内部函数调用/无真实外部副作用的模拟流程一律不构成端到端验收；外部资源暂不可用应如实记录 BLOCKED 或未验证，不得把模拟通过登记为真实端到端 PASS；
②**必须 fail-closed**——外部资源不可用/请求超时/响应格式不符契约/外部执行结果无法确认/关键身份状态或关联信息缺失/无法确认操作是否已发生时，必须停止成功路径，尤其避免超时后盲目重试造成重复执行；
③**DEC-017 原有约束不解除**——单助手长响应核心路径/稳定 DOM/公开 GitHub SHA 读取已验证，多单元和虚拟列表恢复能力尚未验证；PASS_WITH_CONSTRAINTS 不得扩大解释为所有场景 PASS；
④**限定 D1′ 范围**——以已批准交付范围为准，不得顺手扩大为 DEC-017 扩展场景解禁/C2 扩展能力开发/冻结契约修改/全量 Phase 1 验收/未经授权的生产发布。

## 6. 验收标准

1. §2 九步每步有可复现证据（命令+输出+SHA）；
2. 真实 GPT 规划回复 ≥1 轮，经 Schema/三 ID 校验并 M1 登记成功；
3. 真实 commit 经 M4 采集且 SHA 独立可验证；
4. 全链状态推进均经 M1 REST，audit_logs 完整；
5. 结论三态如实：全链通 = PASS；任一步 fail-closed = 按实际登记（BLOCKED/REWORK），**不得将网页自动化失败伪装为 GPT 完成**（06 §3 验收红线）；
6. **零 mock 红线（v0.3 新增，DEC-024-C ①）：** 九步中任何一步的"真实外部交互"若实际以模拟替代（无论登记为成功还是失败），整体结论不得登记 PASS——只允许三态中的 BLOCKED/REWORK 并如实注明模拟替代点。
