## 1. 设计原则

1. **简单直白**：一级目录见版本名，clone 即知，跨电脑复用零额外解释。
2. **不推倒重来**：现有已开发体系定位为**中级版（Standard）基础**（用户拍板修正，DEC-044——app/ M1-M4、contracts/、phase1/ 治理、handoff/）**不物理搬迁、不得删除**，归属映射登记于 standard/README.md。
3. **复用优先**：Basic 开发**可直接从中级版资产复制初级功能**（用户指示 DEC-044）；复制不得改动中级版资产本体；公共工具仍"引用不复制"。
4. **历史证据路径不失效**：phase0/、phase1/ 历史日志与工具目录原地不动，**不得移动、重命名**历史证据及现有工具。
5. **版本目录按需生长**：Basic 目录先建"做什么+做过的记录"，工具目录有自有工具时再创建，不预建空壳（共识修正项）。

## 2. 目录规划

| 目录 | 归属 | 内容 |
|---|---|---|
| `basic/` | AIEO Basic 初级版 | `WORKFLOW.md` 六模块流程规范；`templates/` 任务书/验收请求/交接包模板；`tasks/<任务ID>/` 每任务全记录（需求-方案-步骤-验收-交付）。**不预建空 tools/**——Basic 需要自有工具时再创建（共识修正项） |

| `advanced/` | AIEO Advanced 高级版 | 占位 README（S4/S5 面向，未来以中级版为起点演进），不预定义结构 |

## 3. 派单工具复用（共识：选项 A）

- `basic/` 不复制脚本：WORKFLOW.md 以**仓库相对路径**直接引用 `phase0/tools/gpt_dispatch.mjs` 等已验证工具，并注明依赖（node、playwright、Chrome profile、会话锁）与调用方式。
- **唯一权威源码在 phase0/tools/**，Basic 只引用不复制，避免双份维护；未来若 Basic 独立分发再迁移。

## 4. 工具包（toolkit/）首批两项（共识：先做两项，暂不扩张）

1. **check-push.mjs**：git 推送诊断与执行（L-014 路径固化：先绕仓库代理直连 → 失败探测活代理端口重试 → 仍失败输出精确报告）。共识附加约束：**执行前需确认；诊断失败不得擅自改变 Git 配置**（只报告，改配置由人决定）。
2. **check-env.mjs**：环境体检——代理端口监听、Chrome CDP、node/git 版本、仓库 ahead/behind。共识附加约束：**Linux/Windows 环境识别，端口可配置**（不硬编码 10391/6822）。
3. 后续按真实故障沉淀新工具，**不提前造工具**（共识原话）。

## 5. 风险约束（共识 D 项五条，实施时全部落实）

1. **跨电脑**：禁止依赖个人绝对路径、用户名和固定代理端口。
2. **路径**：脚本统一通过 Git 根目录定位，不依赖启动目录。
3. **双份维护**：指定唯一权威源码，Basic 只引用，不复制。
4. **历史兼容**：不得移动、重命名历史证据及现有工具。
5. **README**：明确版本归属、依赖关系和调用示例。
