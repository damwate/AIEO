# AIEO 版本目录与工具包落位方案 v0.1（草案——待 ChatGPT 共识讨论 + 用户拍板）

**日期：** 2026-11-14
**依据：** DEC-037 纪要（分级路线／§四 Basic 建设原则／§七现有成果不推倒重来）；DEC-039/DEC-040（版本选型制度与复审修正）；DEC-041（复审 PASS）；用户 2026-11-14 指示（先规划目录再开发 Basic MVP；高频小问题工具沉淀进工具包；工具放哪与 ChatGPT 讨论）。
**状态：** 主会话草案 v0.1，开工会议第一题。

## 1. 设计原则

1. **简单直白**：一级目录见版本名，clone 即知，跨电脑复用零额外解释。
2. **不推倒重来**：现有高级版资产（app/ M1-M4、contracts/、phase1/ 治理）**不物理搬迁**，用 README 登记归属映射。
3. **历史证据路径不失效**：phase0/、phase1/ 历史日志与工具目录原地不动。
4. **版本目录自包含**：每个版本目录 = 做什么（WORKFLOW）+ 用什么（tools/templates）+ 做过的记录（tasks/）。

## 2. 目录规划（提案）

| 目录 | 归属 | 内容 |
|---|---|---|
| `basic/` | AIEO Basic 初级版 | `WORKFLOW.md` 六模块流程规范；`tools/` 派单与记录工具；`templates/` 任务书/验收请求/交接包模板；`tasks/<任务ID>/` 每任务全记录（需求-方案-步骤-验收-交付） |
| `standard/` | AIEO Standard 中级版 | 暂建占位 README（定位一句话），迭代时填充，不预建复杂结构 |
| `advanced/` | AIEO Advanced 高级版 | README 登记资产映射：调度器=`app/`、契约=`contracts/`、治理=`phase1/`——物理位置不动，归属在此指认 |
| `toolkit/` | 通用工具包（跨版本共用） | 环境与连接诊断等高频小问题工具（用户指示沉淀处），README 登记清单与用法 |
| 其余现有目录 | 现状不变 | docs/ 治理、phase0/ 与 phase1/ 历史证据、app/、contracts/、runtime/、tests/、handoff/ 各归其位 |

## 3. 工具包（toolkit/）首批清单

1. **check-push.mjs**：git 推送诊断与执行——把 L-014 固定路径固化成脚本：先绕仓库代理直连 → 失败则探测 10391/6822 等活代理端口重试 → 仍失败输出精确报告（哪个连接/报错原文/需要人做什么）。直接治"提交不了找代理"问题。
2. **check-env.mjs**：环境体检——本地代理端口监听状态、Chrome CDP 9222 状态、node/git 版本、仓库 ahead/behind，一次跑完出结论。
3. 后续实战新踩的小问题 → 按同样方式沉淀为脚本并登记 README（只增不删，与 L-014 联动更新）。

## 4. Basic 派单工具复用方式（待讨论关键点）

- **选项 A（倾向）**：`basic/tools/` 不复制脚本，WORKFLOW.md 直接引用 `phase0/tools/gpt_dispatch.mjs` 等现有验证过的工具（同仓库 clone 后路径即达；零重复零双份维护）。
- **选项 B**：复制最小集到 `basic/tools/`（目录自包含更强，但产生双份维护风险）。
- 判据：Basic 不追求目录与仓库解耦（短期不独立成库），零冗余优先；若未来 Basic 要独立分发再迁移。
