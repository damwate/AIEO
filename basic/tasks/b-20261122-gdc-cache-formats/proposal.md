# 任务2 方案：GDC 图片资源准入、加载生命周期与截图完整性治理（本轮只评审不改码）

依据：本地分析 analysis.md + ChatGPT 裁定 acceptance/reply-r1.txt（SHA256=02b77989c40a6e75b673a2b0055fe796a98a6da905d3431ab2bd700f63cef7c5）。

## 结论

- 漏网是**结构性的**（现网数据未踩雷纯靠数据端自觉）：材质路径仅认 webp/png/jpg/jpeg；catalog 种入非白名单扩展参考图会以 octet-stream 直发 AI Worker（external_jobs.py:47）；材质路径 .ktx2 404 无回退=永久纯色。
- 白板直接成因：billboard 未加载渲染**纯白大面片**（billboard.ts:122 brightness=1）+ 截图门只等 GLB（ThreeView.tsx:544）+ photo() 零门禁 + 上传前零像素校验。

## 方案（ChatGPT 裁定采纳）

**定性升级（审查方意见）**：不要定义成"图片格式兼容修复"，定义为 **「GDC 图片资源准入、加载生命周期与截图完整性治理」**——三个层次：①输入资源准入不完整 ②渲染资源加载状态未进截图门禁 ③加载失败缺降级与错误传播。

### 整改项（按裁定优先级）

| 级 | 项 | 裁定内容 |
|---|---|---|
| **P0** | 白板直接成因修复 | ①Billboard 未加载**不显示面片**（渲染规则：未加载不显示/成功显示/失败不显示+记录资源错误）②capture gate 扩展等待：GLB+3D材质纹理+billboard+树贴图+其他场景图（全部"是"），GPU 资源上传准备"需要考虑"③超时不许把不完整画面当成功；失败返回明确错误④**photo 路径必须补门禁**（不能只修 ThreeView 截图） |
| **P0** | 非法格式堵截 | 三层约束：上传入口（魔数+MIME+扩展名）→ **build_catalog 构建期校验实际资源**（不只查配置声明）→ Worker 出口 415 拒绝（octet-stream 不得出闸）。白名单维持 4 种；SVG/GIF/BMP/AVIF/HEIC 明确拒绝。构建期拦截与运行时校验**不能互相替代** |
| **P1** | 材质容错 | KTX2 404 加回退：首选 404/失败→尝试合法备用资源→备用也失败→标记材质失败→**明确错误占位材质，禁止静默成功**；区分 404/解码错误/网络中断/跨域失败；回退资源必须过格式校验防无限尝试；失败留 URL+错误类型+回退结果；**截图必要资源的失败必须向 capture gate 传播** |
| **P1** | 缓存生命周期治理 | 3D 纹理 Map 键纳入 mapUrl/资源身份（修"换图命中旧纹理"）；预览 LRU 与 Plan 生命周期失效规则明确化 |
