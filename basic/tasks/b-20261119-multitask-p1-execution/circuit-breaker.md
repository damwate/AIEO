# P1 批次熔断就绪规范（人工熔断，b-20261119-multitask-p1-execution）

- **性质：** P1HANDOFF-R1 七项前置核验⑥"熔断就绪"的落地文件（2026-11-20）。**人工熔断，不是自动熔断**——无自动监控实现、不声称自动熔断已就绪（P1 执行 R1 裁定约束）；执行主体=当前执行会话（ZCode），按本规范逐条执行并登记。
- **授权依据：** 用户"OK，P1开始吧"（DEC-113）+ P1HANDOFF-R1 S2（DEC-116）；红线对照 DEC-010。

## 一、触发矩阵（五类，MULTITASK-IMPLEMENTATION-PLAN §五 冻结口径）

| 类别 | 触发条件（本批可操作判据） | 熔断级别 |
|---|---|---|
| 权限越界 | 执行中 attempted 超出 P1 授权边界的动作（M1 写路径/906⑥实测/P2P3/main 合并/生产发布/数据删除/审计任务范围外操作） | **全局** |
| 数据污染 | 审计过程可能污染被审计证据（误改来源任务包文件、误写被测仓库、误删证据目录/文件） | **全局** |
| 证据缺失 | 审计必需证据文件在冻结 SHA 下不可读/缺失，或五件套必需文件缺失/为空 | 单任务 |
| 状态不一致 | task_id/被测 SHA/会话 UUID/指针/证据目录任一与登记不符；派单前检查任一项 FAIL | 单任务 |
| 重复失败 | 同一审计任务连续 ≥2 次 REJECT 或 ≥2 次 fail-closed（触发 L-019 止损：停止整改循环→三方会商→再定） | 单任务 |

## 二、全局熔断效果与暂停标志

- 触发全局熔断：立即停止一切 P1 派单与采集动作；创建暂停标志文件 `runtime/locks/p1-batch-pause.flag`（内容=触发时间/类别/责任登记指针）；标志存在期间所有派单前检查直接 FAIL。
- 解除：**仅人工解除**——执行会话按纪律处置完毕并在 decision-log 登记处置记录后方可删除标志；涉及数据删除类处置的，按 DEC-010 报用户本人拍板。

## 三、派单前检查（每次 P1 派单前逐项实查，全过才发）

1. 暂停标志 `runtime/locks/p1-batch-pause.flag` 不存在；
2. 会话锁 `runtime/locks/gpt-session.lockfile` 未被活进程持有（存在残留时核对 holder pid 已死方可视为空闲，如实登记）；
3. 审查会话指针 `phase0/logs/gpt-reviewer-session.json` 与当前登记会话一致、无错指（引以为戒：DEC-115）；
4. 简报 ≤1200B、含唯一标记、目标会话正确（审计任务=各自全新会话，非规划会话）；
5. 本轮属 FIFO 下一序（P1-01 → 验收释放 → P1-02），无并行派单；
6. 在途无未收口轮次（无已发送未采集的派单）。

## 四、在途处置

- 发送双验通过但采集 fail-closed：按 L-018 处置序（禁重发→三步诊断→静态 DOM 补采），处置期间不派发下一任务；recoll 派生换全三参数并 grep 核对（CONV_UUID+SENT_USER_UNIT_KEY+FAILED_DIR）。
- 发送结果 UNCERTAIN：先对账（账本+DOM 结构化证据），未证明已接受前禁止重发。

## 五、恢复条件与责任主体

- 单任务熔断恢复：按 L-019 阶梯——停止→三方会商（执行者+审查会话）→会商结论登记→再定续跑/降档/交用户；返工计数语义照 L-019（同一问题常规整改轮次计数，降档验证轮不计入）。
- 全局熔断恢复：见二。
- 责任主体：执行会话负责触发与执行并如实登记；ChatGPT 审查会话负责验收裁定；用户保留手动介入权与 DEC-010 三类红线拍板权。
