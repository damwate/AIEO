R4 付费接口测试方法审议

裁定：推荐采用「官方契约优先 → 本地 Mock 验证 → 只读证据核对 → 单次授权付费验收」四阶段方法。

核心原则：

不用真实 API 调用探索未知参数。

不用 HTTP 200 代替参数契约证明。

不用输出像素尺寸代替计费档位证明。

不用供应商 A 的文档推断供应商 B 的行为。

未经用户明确授权，不产生任何真实生成费用。

一次付费验收不是探索性测试，而是对已经通过前三阶段的方案做最终确认。

本轮方法裁定

方法方向通过

本轮只审议方法，不调用任何真实接口，不产生 API 费用。

官方文档作为参数契约的首要依据。

Mock 证明本地程序实际发送什么。

只读验证证明供应商账户和历史运行状态。

一次付费验收证明真实端到端行为。

建议将证据分成四级：

E2：官方版本证据

E3：官方账户证据

控制台模型目录、账户配额、账单规则、账户实际启用能力。

E4：历史运行证据

注意：E1 与 E2 是接口契约的主要依据，E3 是账户能力的补充依据，E4 是历史行为证据。

它们不能互相替代。

二、本地 Mock 契约测试

Mock 阶段的目标不是证明供应商接受参数，而是证明自己的程序能够正确构造请求。

这是可以完全不产生费用完成的主要验证阶段。

Mock 必须截获最终出站请求，而不是只测试请求构造函数的中间结果。

否则可能出现：

实际 multipart 请求仍然发送错误参数。

因此必须在 HTTP Transport 最后一层记录请求快照。

3. 参考图验证

参考图必须验证实际出站内容。

针对现有生图链路，建议覆盖：

相同原图只发送一次。

不同原图不被错误合并。

图片顺序符合既定契约。

图片内容 SHA256 与源文件一致。

特别注意：

不能只验证 external_ref 数组长度。

必须验证实际 multipart 文件内容。

必须先从真实配置加载代码确认：

缺失配置是否触发隐式默认值。

5. 重试和旧任务兼容

必须区分两种行为。

同一 Job 重试：

不重新选择产品。

不重新生成参考图列表。

不意外改变 prompt。

不改变冻结的请求参数。

不因全局默认值变化而偷偷切换档位。

旧 Job：

不自动注入新字段。

不把历史缺省值解释成新档位。

不重新生成历史任务配置。

按原有兼容策略执行。

无法确定历史参数时，必须明确标记，不得自行猜测。

3. 只读验证的证明边界

例如：

只读查询得到模型存在

可以证明

该账户能够看到这个模型目录项。

不能证明

模型一定可以生成。

模型一定支持 2K。

edits 一定支持 2K。

当前账户一定有对应权限。

调用一定按 2K 计费。

同理，账单显示历史生成扣款，只能证明那笔历史费用，不能证明未来一次请求会使用同一档位。

3. 成本控制

建议采用以下规则：

一次调用、一次任务、一次输出验收。

具体要求：

关闭应用层自动重试。

禁止失败自动降级到其他供应商。

禁止自动重新提交。

设置 HTTP 超时。

记录请求 ID 和供应商任务 ID。

对超时、断连等结果标记 UNKNOWN_CHARGE_STATUS。

在费用状态确认之前，不再次调用。

这里特别强调：

HTTP 超时不等于供应商没有收到请求。

因此失败即停，不允许因为客户端没有收到响应，就再次发送生成请求。
