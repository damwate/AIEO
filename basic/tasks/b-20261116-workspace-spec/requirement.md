# AIEO 多项目、多 IDE 工作区管理规范

请在 AIEO 仓库中执行本项文档任务。

## 一、任务目标

为 AIEO WORKFLOW v0.3 增加《多项目、多 IDE 工作区管理规范》，明确 AIEO 控制层与业务项目执行层的职责边界。

## 二、执行要求

1. 首先检查当前 Git 分支、工作区状态和最新完整 Commit SHA。
2. 阅读 basic/WORKFLOW.md、AGENTS.md、相关架构文档、C1–C8 契约和 DEC 决策记录。
3. 不得覆盖或破坏 WORKFLOW v0.3 已有规则。
4. 仅修改本次规范所必需的文件。
5. 如果发现与现有契约或决策冲突，停止修改并报告，不得自行改变既有决策。

## 三、新规范必须覆盖

1. AIEO 工作区与业务项目工作区的职责边界。
2. 一个开发任务如何指定目标仓库、分支、工作目录。
3. CodeBuddy、ZCode、Codex 等不同 IDE 的统一执行规范。
4. AGENTS.md、项目 Rules、Skills、MCP 的项目级配置原则。
5. 任务包如何交付给执行端。
6. Commit SHA、Diff、测试结果如何回传 AIEO。
7. GPT Review、测试、审计和用户批准的衔接。
8. 多项目任务如何拆分，如何避免在错误仓库修改代码。
9. 执行失败、上下文不足、工具不可用时如何升级处理。

## 四、边界约束

- AIEO 是任务控制中心，不是所有项目的代码执行目录。
- 普通业务开发直接在目标业务项目根目录启动 IDE。
- AIEO 自身开发仍在 AIEO 仓库进行。
- 不允许将未实现的自动化能力描述为已经实现。
- 不得降低现有 GitPointer、全 SHA 证据和 fail-closed 要求。
- 不得擅自修改已有 DEC 决策。

## 五、验收要求

1. 文档结构完整，职责清晰。
2. 与 WORKFLOW v0.3 保持一致。
3. 不存在重复、冲突或无法执行的规定。
4. 相关检查和测试通过。
5. 提供完整 Git Diff。
6. 提供修改文件清单及完整 Commit SHA。

## 六、Git 操作要求

先完成修改和检查。

提交前暂停，向用户报告：
- 修改文件
- 主要变更
- 检查结果
- 完整 Git Diff
- 建议 Commit Message

等待用户批准后再执行 Git Commit。

不得直接推送远程 main，除非另行获得明确授权。
