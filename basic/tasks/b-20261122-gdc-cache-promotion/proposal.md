- "只有 3D 页做了缓存"属实（5 层全进程内存级，刷新即失；nginx 把 /assets 压 no-cache）。

## 方案（ChatGPT 裁定采纳）

另：Vite hash 产物（已 immutable）与业务资源（no-cache）不得混为一谈；版本化 URL 不得破坏 2D 预载 images 键与 expectSrcs 匹配。

### Q2 推进顺序：A → B → C（C 加安全门禁）

- **P0-1 A 资产版本化合流**（修 80MB 次日重拉/2D 24MB 重复）：验收门=首载带版本、再进零重复传输、同名替换新 URL 新字节不命中旧纹理、KTX2 v/kv 各自匹配、冷热跨方案+硬重启全过、缺版本/错误响应/版本不匹配一律不授长期缓存。
- **P0-2 B AI 结果图 immutable**（独立资产身份缓存）：验收门=同 asset_id 不可原位覆盖、内容变化必产生新身份/新版本 URL、跨用户/项目/方案无越权、失败响应不缓存、替换/删除/撤回/历史快照引用有回归测试。A、B 可并行设计但**分开提交分开验收**（防归因困难）。
- **P0-3 C 分享页去 no-store**（**安全门禁后实施**）：审查方核查 publication.py:973 端点先验 Publication 再验资产属快照再读媒体——no-store 可能承担**分享撤回后的访问控制语义**，非历史遗留。典型风险链：客户取得图→管理员撤回→客户再用旧缓存绕过撤回检查。验收门=撤回后服务端必须拒绝、不得绕 token 授权、token/账户隔离、区分私有缓存与公共代理缓存、静态 JS/CSS 可单独缓存但授权媒体接口不放开。

### Q3 hidden 资产 1h 延迟：分语义裁定

纯展示隐藏=可接受 1h；隐藏=撤权=**不接受**（缓存不得替代服务端授权，no-cache 也不行）；历史快照引用=接受（与当前可见性分离）；隐私/私有媒体=严格授权必要时 no-store。另注意 HTTP 语义：no-cache=可存储须重验、no-store=不许存储、max-age=3600=1h 内可不重验。

### 四条架构红线（审查方锁定）

①不引入前端持久化新体系（首期普通 HTTP 缓存，不加 SW/IndexedDB/CacheStorage）②不扩大 2D 预载范围 ③不混淆资产版本（内容 SHA-256）与业务版本（catalog 版本/mtime）④不以缓存替代授权。
