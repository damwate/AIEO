# L-018 §6 改写稿 + 一轮一会话派单流程改造方案 R1（SESSION-ARCH-R1 裁定实施稿，供定点验收）

- **依据：** DEC-132（SESSION-ARCH-R1 裁定：一轮一会话为新常规机制+四硬约束；§6 改"长任务/在途恢复例外"；清理=批次清单+用户批准）。
- **范围声明照登：** 本稿为文档与流程方案，不含代码改动、不含清理执行、不含 N=2 重启授权。

## 一、L-018 §6 改写稿（替换原"会话上下文上限"条目）

**常规流程（一轮一会话，新基线）：**
1. 每轮派单使用 `--new-session` 创建独立新会话，一段对话只承载一问一答；回复采集、证据归档完成后该会话不再复用。
2. 四硬约束：**简报全自包含**（本轮审查目标+仓库/分支/完整 SHA+范围+决策编号+背景+验收标准+禁止事项，禁依赖上一轮上下文补全）；**每轮按指定 SHA 重新读取 decision-log**（裁定以本轮 SHA 下的记录为准，SHA 下记录与简报冲突→停下报告冲突）；**失败即弃不重发**（UNCERTAIN/采集失败/fail-closed 保留现场证据，重试=单独授权的新动作并明确处置前轮不确定状态）；**会话与证据解耦**（ChatGPT 会话仅临时载体，仓库归档+reply SHA 才是审计依据；归档成功≠允许删除 ChatGPT 侧会话）。
3. 并行实例：每轮归档身份独立（dispatch 目录+result.json session_id 唯一），不依赖共享 reviewer 指针识别本轮结果；一轮一会话≠一轮一个账号（N 实例仍共享账号级风控约束，C9 不变）；新会话≠新浏览器（不改 profile/端口/实例锁/浏览器生命周期）。

**例外流程（兼容性例外，非常规选项）：**
- 仅对确实无法拆分、必须在同一会话内连续完成的长任务，或历史在途任务恢复，允许申请会话迁移；申请须说明不可拆分原因+迁移目标+上下文完整性验证方式，经用户明确批准后执行。
- 失败边界：迁移失败/目标会话归属不明/采集状态不确定→立即停止；不自动重发，不把失败迁移降级为无证据的新会话续跑。

**清理机制（与迁移解耦）：**
- 历史一次性审查会话清理=批次清单（会话标识+对应派单归档路径+reply SHA+审查状态+未解决项标注）+用户逐批明确批准后执行；默认排除在途/失败现场待处置/争议/证据链未核验会话；每批记录批准依据、范围、结果、未删除项。
- DEC-010 未明确授权前按现状保留，不设自动过期；"历史较久"不作为唯一删除条件。
- Temporary Chat：后续单独小规模验证（临时模式标识/发送/采集/归档关联/退出后不可恢复），通过前不替代普通 --new-session。

## 二、--new-session 派单流程改造方案

1. **审查轮派单模板：** `--new-session --no-update-pointer` + 全自包含简报（按 §一.2 四硬约束清单逐项核对，首行 [TAG|...] 标记 ≤80 字符内——R3 教训）。
2. **指针语义：** --no-update-pointer 为常态；共享 reviewer 指针降级为"最近审查会话参考记录"（不用于归属判定——归属以 dispatch 归档 result.json session_id 为准）。
3. **采集预期：** 新会话短 DOM，采集成功率大幅提升（本日实测多轮首派即采成功）；fail-closed 仍走 L-018 补采（新增中段采集语义：after 以"下一个 user 单元"为界——同会话多轮并存时本轮归属区间边界，已在 recoll_p2fix_r3 实装验证）。
4. **机制影响评估（照 DEC-132 ④）：** C9/实例域锁/实例内串行跨实例并行/profile 端口——全部保持原样；每轮归档身份独立核验列为实施验收项。
5. **收益对价（照裁定口径）：** 每轮简报准备+decision-log 重读成本增加，换取上下文隔离、采集稳定性、可复核性——裁定已认可该成本。
6. **实施验收项：** 提交后由审查方定点验收改写稿与流程方案本身（本提交 SHA）；机制改造不授权 N=2 重启（重启仍按 DEC-129 序列）。
