- **依据：** DEC-130（P2-COUNT-R1 裁定，reply SHA-256 见 decision-log §DEC-130）；审查方要求"甲方案、克隆初始化检查、C6 指标采集字段及逐级扩容规则整理进 Git"。
- **性质：** 阶段2/阶段3 运营依据文档；本轮批准的是架构与运营方案，非生产扩容授权。

## 一、登录态甲方案：受控克隆规程（DEC-130 有条件批准）

1. **黄金源 profile：** `runtime/chrome_profiles/gpt-poc`（default 实例，已登录）。克隆前核对账号身份有效、无安全验证页。
2. **全关前置：** 克隆时所有 Chrome 进程必须已退出（含后台）；运行中热复制禁止。
3. **完整复制：** 整目录拷贝（含 Local State 与 Profile 数据），目标=`gpt-poc-<instance>`；已有残留目录先删除再镜像（robocopy //E，残留=extras 会带入脏状态——C1 首跑实证）。
4. **实例隔离硬约束：** 每实例独立 user-data-dir/DEBUG_PORT/INSTANCE_ID/锁；**禁止两个 Chrome 进程共用同一份 profile**；禁止自动循环重登。
5. **逐实例登录态验收：** 逐个启动→人工核对已登录+账号身份正确+无安全验证/限流页（不读取导出 Cookie、凭据不入日志）；全部通过才开放并发派单。
6. **失败处置表：** 克隆后未登录→停该实例查黄金源；登录态失效→暂停该实例人工恢复或重克隆；安全验证→停止自动化人工处理；账号安全提醒→全实例暂停按账号级安全问题处理；Chrome 残留进程→不覆盖不重拷，先确认归属；429→进入 C9 统一退避。
7. **黄金源更新：** 仅在全部 Chrome 关闭时更新黄金源，更新后再生成实例副本。

## 二、生产规模与扩容路线（DEC-130 裁定）

- **生产首选 N=3**（N=4=条件扩容：N=3 仍真实任务积压且配额/风控/资源有余量才申请验证）。
- **扩容路线（逐级，不直达）：** N=2 阶段2 试跑 → C6 观察期（**≥5 个工作日且 ≥50 次有效派单**，样本不足延长不降标）→ N=3 受控扩容试跑 → 再观察 ≥5 工作日（对比 N=2/N=3）→ 生产规模裁定（N=3 或 N=4）。
- **扩容经济性指标：** N=3 相对 N=2 的成功吞吐提升、N=4 相对 N=3 的边际吞吐提升——增实例只看总请求数不算数。

## 三、C6 观察期数据清单（六类，正式验收要求）

| 类 | 字段 |
|---|---|
| A 吞吐与效率 | 总派单量（日/每实例）、成功数、FAIL/BLOCKED 分列、每小时成功任务数、响应时间 P50/P95、排队时间、并发利用率 |
| B 账号配额 | 观察期初始额度（可读时记录）、每日消耗、每任务平均消耗、额度恢复时间/量、消耗速度、剩余余量——官方无精确余量数字时登记可观测信息，禁自算虚假精确配额 |
| C 429 与风控 | 429 真实次数、发生时实例数/并发量/时间、页面原始错误形态、C9 是否成功写入、其他实例是否停止、退避期限是否被缩短、安全提醒/异常登录/会话失效——**无真实 429=NOT_OBSERVED 不记 PASS** |
| D 实例稳定性与隔离 | Chrome 异常退出/CDP 断连/profile 失效/端口冲突/实例锁冲突次数、清理 A 时 B 是否正常、补采是否回原会话、跨实例串档、不明副作用 |
| E 机器资源 | 每实例与整机 CPU 平均/P95、内存平均/峰值、Chrome 进程数、异常残留、磁盘日志增长 |
| F 扩容判断表 | 串档/误杀/未知副作用→停止扩容；账号级风控异常→停止并复核 C9；配额不足→不增实例；N=3 吞吐明显提升且稳定→可考虑 N=3 生产；N=3 仍积压→申请 N=4 验证；N=4 只增消耗无收益→保持 N=3 |
