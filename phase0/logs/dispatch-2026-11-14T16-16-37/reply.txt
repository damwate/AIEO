二、必须修改的问题
P1-1：TCP 探测超时被错误归类为「TCP 未监听」

代码位置： toolkit/check-push.mjs

当前 probePort()：

JavaScript
s.setTimeout(timeoutMs, () => done(false));
s.once("connect", () => done(true));
s.once("error", () => done(false));

它只返回布尔值，导致以下两种情况无法区分：

目标端口明确拒绝连接。

2 秒内没有完成 TCP 连接，触发超时。

随后 probeCandidate()：

JavaScript
const alive = await tcpProbe(candidate.port);
if (!alive) {
  return {
    tried: [{
      label,
      port: candidate.port,
      ok: false,
      timedOut: false,
      stderr: "TCP 未监听",
      ms: 0
    }],
    win: null,
    tcpSkipped: true
  };
}

这里直接把所有 false 归类为「TCP 未监听」。

问题性质：

这与本次整改明确要求的：

本次探测超时 ≠ 路径永久不可用。

存在语义冲突。

TCP 探测超时同样不能证明端口没有监听，更不能证明代理路径不可用。

最小整改要求：

probePort 返回结构化结果，至少区分连接成功、连接失败、超时。

probeCandidate 保留 TCP 超时状态，不得统一标记为「TCP 未监听」。

超时记录应明确标注本次探测超时，不代表路径永久不可用。

TCP 超时仍然可以跳过本次 dry-run，继续下一候选，不改变候选顺序。

增加实际覆盖 TCP 超时、连接拒绝、连接成功三种结果的测试。

不要求扩大工具范围，也不要求改变现有发现与验证架构。
