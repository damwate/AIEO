二、A 方案需要增加的独立性约束

我建议将 A 升级为 A+，增加以下六项约束。

1. 聚合包必须绑定审查 commit

聚合包必须满足：

来源必须是本次指定的 Git commit。

使用 git archive 从指定 commit 导出。

包内路径必须与 manifest 中的 95 个路径完全一致。

不允许从工作区直接打包。

不允许打包后修改文件内容。

聚合包必须提交到仓库，并随指定 commit 固化。

例如：

Bash
git archive \
  --format=tar \
  --output=phase1/manifests/T-P1-903-input-bundle.tar \
  <COMMIT> \
  <95个指定路径>

注意：如果聚合包本身也在该 commit 中，就会产生自引用问题。

因此应采用两阶段设计：

先生成输入聚合包。

将聚合包加入仓库，形成最终审查 commit。

manifest 明确记录原始文件哈希，聚合包记录独立 blob SHA。

不能要求聚合包包含自身。

2. 必须核验聚合包自身 Git Blob

不能仅凭 GitHub 页面显示的文件名、大小或下载成功就信任聚合包。

引导包必须明确要求：

获取聚合包对应的 Git Blob SHA。

从指定 commit 的 Git Tree 确认聚合包路径。

核验其 blob 对象身份。

下载聚合包原始字节。

独立计算 SHA-256。

记录下载字节数和 SHA-256。

这里需要区分：

Git Blob SHA-1 与 SHA-256 文件摘要不是同一个概念。

Git Blob SHA-1 应按 Git 对象规则计算：

纯文本
SHA1("blob " + size + "\0" + content)

文件 SHA-256 则直接对原始文件字节计算。

两者都应记录，不能混为一谈。

3. 必须完整核验 95 个文件

这是 A+ 的核心。

审查者下载 tar 后，必须：

检查实际文件数量。

检查文件路径集合。

检查是否有重复路径。

检查是否有额外文件。

检查是否有缺失文件。

对全部 95 个文件逐一计算 SHA-256。

对照 manifest 中的 SHA-256 和 size。

通过标准：

95/95 全部一致

不能用抽查代替全量哈希核验。

五、最终建议

A+：聚合包全量核验 + 15 文件独立抽查。
