问题6：ST-01 多 commit 核验仍有操作缺口

已经通过的部分：

增加 git show -s --format='%H %P' <待验收commit>。

单 commit 明确要求 parent 等于申报基线。

多 commit 明确要求首端为基线、尾端为待验收 commit，且链上不能有 merge commit。

本次模板也同步增加了单 commit parent 和多 commit 无 merge 的要求。

仍未通过的部分：

git show -s --format='%H %P' <待验收commit> 只能直接显示待验收 commit 本身及其 parent，不能单独证明多 commit 区间内每一个 commit 都是线性连接，也不能证明中间没有 merge commit。

当前条款没有给出多 commit 情况下的完整核验命令和逐项判定条件。git rev-list --count 只能核对数量，也不能替代 parent 链验证。

模板中的多 commit 规则比 WORKFLOW 更简略，也没有补上这个缺口。

最小整改建议：

增加一条多 commit 核验命令，例如：

Bash
git rev-list --reverse --parents <基线>..<待验收commit>

并明确通过条件：

输出的第一条 commit，其唯一 parent 必须等于基线。

后续每条 commit 必须只有一个 parent，且 parent 等于上一条 commit 的 SHA。

最后一条 commit 必须等于待验收 commit。

任意一条出现多个 parent，即存在 merge commit，不能按普通线性多 commit 申报；应按 WORKFLOW 要求改报 diff 基线并单独说明。

将这套多 commit 核验方法同步到 acceptance-request.md 模板。

这样才能让执行者拿到规则后直接复跑，而不是自行猜测如何检查。
