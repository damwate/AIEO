三、问题清单
问题1：R4 和 numstat 的 Git 命令失败可能被错误放行
阻断验收

文件：toolkit/check-binding.py

R4 当前实现：

Python
运行
rc, out, _ = try_git(repo, "rev-list", f"{ns.target}..HEAD")
descendants = out.splitlines() if rc == 0 and out else []

这里没有处理 rc != 0。

当 Git 命令失败时，descendants 被赋为空列表，随后可能执行：

Python
运行
rules.append(Rule("R4", "PASS", "待验收 commit 无后代（=当前 HEAD），为最终申报对象"))

也就是说：

实际上没有成功核验最终性；

工具却可能报告 R4 PASS；

最终聚合 verdict 也可能成为 PASS。

同样的问题还出现在：

Python
运行
rc, out, _ = try_git(repo, "diff", "--numstat", ...)
if rc == 0 and out:
    numstat = ...

numstat 获取失败时，工具静默返回空数组，仍可能保留 PASS。

违反的要求：

B5：Git 异常必须 BLOCKED。

工具自身声明的 fail-closed 安全边界。

WORKFLOW 对无法核验不得视为 PASS 的约束。

整改要求：

R4 命令非零退出必须明确输出 BLOCKED，不能生成 R4 PASS。

numstat 命令失败也必须进入 BLOCKED，不能静默返回空证据。

增加故障注入测试：仓库探针和对象存在检查成功后，分别使 R4、numstat 命令失败，验证最终 verdict 为 BLOCKED、退出码为 2。

正常情况下的 R4 PASS 和 numstat 输出仍须保持原行为。

问题2：B2 测试没有完整验证负例中的 commit 身份
需整改

负例测试虽能命中部分规则和原因，但没有完整断言规则输出中的 commit SHA。

整改要求：

对 R2 断链、R3 merge、R4 过期 target、R6 对象不存在等有具体对象的负例，断言 commits 包含预期 SHA。

对 R1 数量不匹配等不对应单个具体 commit 的情况，明确验收其数量差异字段，不强行虚构对象。

对 R7 空区间，断言规则 ID、BLOCKED 原因和退出码。

确保每个负例都验证具体拦截规则，而不是仅检查最终退出码。
