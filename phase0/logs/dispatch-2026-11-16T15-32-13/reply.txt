SHA256 上下文语义

这一项我重点核对了 classify() 的顺序：

先识别完整 UUID 格式片段。

再检查当前 token 之前的行内文本是否匹配 SHA256 标记。

SHA256 上下文命中时，直接返回 CAT_SHA256，不会继续执行 Git 前缀唯一命中补全。

因此，普通十六进制截断片段即使恰好是某个 Git commit 的唯一前缀，也会进入未知项，触发 fail-closed。

这解决了 R21 中“SHA256 截断片段碰巧命中 Git 唯一前缀，就被错误补全”的问题。完整 64 位 SHA256 不在 7～39 位 token 扫描范围内，也符合脚本注释中的约定。
