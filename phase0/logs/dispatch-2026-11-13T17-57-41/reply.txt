三、A 方案强制约束清单

以下约束建议全部列为 MUST，而不是 SHOULD。

A. Manifest 约束

每个文件必须有唯一相对路径。

每个文件必须有 Git blob SHA-1。

每个文件必须有预期 size。

每个文件必须有 SHA-256。

manifest 必须记录固定 commit。

manifest 必须与固定 tag / commit 锚点绑定。

文件路径不得重复。

不允许通过通配符、模糊匹配或目录级匹配代替逐文件身份核验。

B. 独立审查者入口门禁

必须读取正式 bootstrap。

必须读取索引及 manifest。

必须执行一次完整 tree 身份获取。

必须逐项比对 95/95 文件 blob SHA-1。

必须比对全部 14/14 分片身份。

必须比对索引身份。

任意一项不匹配，立即 BLOCKED。

缺少文件、重复文件、额外文件均不得静默忽略。

不得将无法读取的二进制正文声明为已审查。

入口身份门禁通过后，才允许进入实质审查。

C. 主会话本地完整性门禁

必须在受控本地环境执行 manifest_tool recheck。

必须执行 verify。

必须完成全部分片解码。

必须完成 TAR 解包。

必须完成 95/95 文件 SHA-256 与 size 核验。

任意文件不匹配，不得发布正式审查材料。

必须保存机器验证结果。

必须将验证结果绑定到对应 commit 和 tag。

重新打包或修改任何材料后，必须重新执行完整验证。

不得以 GitHub 页面显示成功代替本地验证。

D. 实质审查约束

审查者必须直接读取审查对象的原始文本文件。

不得仅依据 bootstrap 摘要作出通过结论。

不得把身份核验通过等同于实质审查通过。

二进制材料只能报告身份已核验，不能报告内容已审查。

发现实质问题仍然按照原三态规则判定。

不得因为环境能力限制而降低缺陷严重程度。

不得把入口 BLOCKED 解释成材料缺陷。

四、建议增加的治理边界

我认为还需要补充三个容易被忽略的问题。

1. 两个验证结果必须独立记录。

建议最终审查报告明确区分：

OBJECT_IDENTITY_GATE：审查者完成。

BYTE_INTEGRITY_GATE：主会话本地工具完成。

两者分别记录 PASS / FAIL / BLOCKED。

不能合并成一个笼统的 PASS。

2. 主会话验证不能冒充独立审查。

主会话可以证明材料符合入库完整性要求，但不能替代独立审查者对实质内容的判断。

这是治理独立性的关键。

3. 环境能力变化应允许重新升级门禁。

如果未来审查环境具备代码执行、二进制读取和本地哈希能力，可以恢复 A+ 字节级独立核验。

A 不应该成为永久降低标准的理由，而应该是当前环境条件下的正式执行协议。
