③ 两个必须写进方案的边界

边界一：临时目录 Clone 不等于真正的新电脑。

在同一台电脑上创建临时目录，仍然共享本机的 Node、Python、Git、系统代理、全局 Git 配置、Chrome 和用户凭据。

所以报告必须分开写：

仓库复制验证： 干净目录 clone 后，仓库文件和脚本能否正常工作。

环境初始化验证： 依赖安装、profile 初始化、外部工具配置能否按步骤完成。

新电脑完整验证： 当前演练没有实际换电脑时，只能标记为“本机模拟验证”，不能声称已经完成跨电脑实测。

建议至少记录环境变量、Git 全局配置、Node/Python 版本、系统代理状态，以及是否使用已有登录态。

边界二：诊断不等于推送。

check-push 只运行：

Bash
node toolkit/check-push.mjs

禁止使用 --push 或 --yes。它的诊断模式会进行 Git dry-run 探测，但不应执行真实推送。执行前后核对 .git/config、分支和工作区，确认没有产生实际推送或配置修改。

此外，check-env 的输出不能替代人工核验，也不能因为环境依赖缺失就擅自修改检查器。
