二、跨方案验收补齐
FAIL — 用例未形成有效的跨方案验收

核对文件：

src/frontend/e2e/web-demo-cache-cross-scheme.spec.ts

认可的设计：

使用浏览器 performance.getEntriesByType('resource')。

使用 transferSize === 0 判断本机缓存命中。

没有采用 Playwright request 事件作为缓存命中依据。

同一 Page 进行导航，意图保留浏览器缓存。

但是，发现一个实质性问题：

两次调用 openSchemeLibrary()，并没有打开同一项目下的两个方案。

原因是 openSchemeLibrary() 每次都会调用：

TypeScript
setupProject(
  base,
  USER,
  'E2E 跨方案缓存',
  {withScene:false, schemeName}
);

而 setupProject() 内部明确会：

查找同名项目。

归档已有同名项目。

创建新的 Site。

创建新的 Project。

创建新的 Scheme。

因此，方案 A 和方案 B 实际上属于两个不同项目。

这意味着用例测试的是：

两个独立项目之间是否复用浏览器缓存。

而不是要求的：

关闭同一项目的方案 A，再打开方案 B，验证共用素材本机直读。

此外，VERSIONED 正则目前声明后没有使用。

精确整改点：

setupProject() 只调用一次，取得同一个 projectId。

在这个项目下通过现有 API 创建第二个 Scheme。

第一次打开 Scheme A，记录实际加载的版本化素材 URL。

离开 A，再打开同一项目的 Scheme B。

只统计两方案共同使用的素材。

对共同素材逐项检查 transferSize === 0。

不以第一套方案的全部请求数量直接作为第二套方案的预期命中数量。

另外，本轮 E2E 没有实际运行成功，不能认定浏览器缓存验收通过。
