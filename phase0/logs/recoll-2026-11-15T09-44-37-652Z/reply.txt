四、建议的 Basic 整体完成标准 checklist

以下是建议版“产品级 DoD”，与 31 项单任务验收清单分开。每项只允许 PASS / FAIL / BLOCKED；BLOCKED 不得计作通过。

BC-01｜DEC-045 对齐： D1-D5 五项逐项映射到具体文件、实现或实测证据；无未解释的偏离。
BC-02｜独立性： Basic 不导入 Standard/Advanced 运行时模块，不依赖其数据库、服务端、调度器；仓库公共工具及主机级依赖清单完整。
BC-03｜新设备复现（D1/G5）： 在第二台干净设备或可复现的干净 VM 上，从 clone 开始按 SETUP-CHECKLIST 完成初始化；记录 OS、Node/Python/Git 版本、命令、退出码、HEAD SHA、依赖安装、profile 初始化、安全检查及实际阻断项。至少验证 taskpack 检查器和派单/推送路径；如平台限制不支持，必须缩小产品支持声明并经用户确认，不能宣称“复制即用”。
BC-04｜六模块交付： 任务管理、规划协商、开发执行、独立验收、返工管理、交付管理均有可执行规范、模板/记录入口和责任边界。
BC-05｜核心工具： taskpack checker 在干净环境可运行；PASS/FAIL/IN_PROGRESS、六项检查、路径安全、异常输入和 JSON/文本一致性有可复跑测试证据。
BC-06｜代码类流程验证： 至少一个 v0.3 下代码类任务按四步流程完整闭环；代码绑定、测试原始输出、独立六查、返工记录、最终交付和检查器终检均 PASS。不得用文档任务替代。
BC-07｜抽取边界： 无整套架构搬迁/反向运行时依赖；若存在复制件，逐件登记来源路径、源 commit 完整 SHA、修改点、对应测试；若无抽取，明确记录 N/A 理由。
BC-08｜开发纪律： 四步流程、用户授权/节点授权边界、独立验收、三轮止损和 BLOCKED 处置均有真实任务证据；高危操作仍遵守 DEC-010。
BC-09｜任务质量清单： 31 项清单与 WORKFLOW/模板口径一致；整体通过必须全必检 PASS，N/A 有条件说明。
BC-10｜证据和版本： 所有完成声明绑定完整 commit SHA；测试证据可定位、哈希可核；任务数、状态、验收轮次统计口径一致（先解决“5 vs 7”）。
BC-11｜已知限制与 backlog： DEC-043/recoll 等遗留项有负责人、重启触发条件和当前替代流程；不得把已知限制写成已修复。
BC-12｜最终治理签核： 形成一份产品级验收报告，逐项列 PASS/FAIL/BLOCKED、证据链接、未解决项；所有 BC 必办项 PASS 后才允许宣布 Basic 初级版完成。
