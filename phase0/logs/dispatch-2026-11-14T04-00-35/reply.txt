三、发现的遗留问题

虽然六项修订均已落实，但全文复核还发现三个需要收口的地方。

REWORK R1：S0 零副作用与锁文件操作存在文字歧义

位置：§2 S0、§4 重复执行防护。

当前规定 PRECHECK 全部只读，但又将 run 锁文件纳入 PRECHECK。

锁文件的创建、写入本身就是文件系统副作用。

建议明确：

锁文件的原子获取属于运行协调操作，不属于业务副作用。

明确锁获取和 PRECHECK 检查的先后关系。

PRECHECK 失败时如何释放本次取得的锁。

已存在残留锁时不得擅自删除或抢占。

这样才能同时保证单实例安全与零业务副作用。

REWORK R2：S1 同名实体幂等与跨 run 隔离需要明确

位置：§2 S1、§4、§10。

当前同时规定：

S1 创建前查询同名实体。

新 run 创建全新项目、批次、任务。

不复用上次半建制状态。

建议明确实体命名与 run_id 的关系：

同一 run 内重复请求：允许幂等复用。

不同 run：必须使用独立实体标识。

新 run 发现已有同名实体：不得直接认领或复用，按冲突策略停止并登记。

否则实现者可能将同名实体误认为本次 run 的既有资源。

REWORK R3：§6 仍然写九步，与新增 S0 后的十步不一致

位置：§2、§6。

§2 已经明确执行步骤为 S0–S9，共十步。

但是 §6 仍然规定：

RUN-RECORD 九步 ID/SHA 绑定+复盘。

建议修订为：

RUN-RECORD 十步（S0–S9）ID/SHA 绑定+复盘。

同时全文搜索相关的「九步」表述，区分历史上 905 的九步和当前调度器的十步，避免误改历史事实。
