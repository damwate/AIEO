## 1. MAJOR：协议级重写 v3 —— 取消 intent 机制，rename 原子换出 + 世代验证

### 审查指摘（确认属实）

1. intent 文件同样经历"wx 建空文件 → writeSync"窗口；`listIntents` 遇解析失败**静默忽略**而非 fail-closed → 双回收者；
2. "二次读取与 unlink 之间不是原子操作"——旧锁被新锁替换后，迟到回收者按路径 unlink 会删除新锁；
3. 测试未覆盖这些交错。

### 修复：v3 协议（`session_lock.mjs`）

**设计取舍：彻底移除 intent/选举与一切对锁路径的 unlink**（按审查建议的"不会对路径执行无条件 unlink 的原子所有权/替换机制"）：

| 竞态 | v3 消除方式 |
|---|---|
| intent 初始化窗口 | **intent 机制整体删除**（无票据可被静默忽略） |
| 双回收者选举 | 不再选举：**rename 原子换出本身即仲裁**——两个回收者对同一 stale 锁，只有一个 rename 成功，另一个得到 ENOENT 回到创建竞争 |
| 迟到回收者删除新锁 | 回收动作 = `renameSync(lockPath → quarantine-<世代rand>-<myRand>.tmp)`（原子，目标名唯一，绝不覆盖他人文件）；**不对锁路径执行 unlink**。迟到者面对新锁只有两种结局：读到 LIVE 内容 → `SESSION_LOCK_CONFLICT`（零改动）；或 rename 得 ENOENT（锁已正常释放）→ 公平重竞争 |
| 误移他人新锁 | rename 后**世代验证**：读取 quarantine 内容必须与回收前读到的世代（born_at+rand+pid 三元组）完全一致；协议内不可能不匹配（锁内容从不原地修改，只能被整体换出）；不匹配 = 外部篡改 → `LOCK_QUARANTINE_MISMATCH` fail-closed 并保留现场 |
| 初始化窗口 | 保留 v2 的 fd 写入 + 空/损坏锁 fail-closed（有限重试后抛 `LOCK_CORRUPT_OR_INITIALIZING`，绝不删除） |
| 双重持锁 | 持锁 ⟺ wx 原子创建成功（单点裁决，不变量保持） |

不变量汇总：**unlink 只发生在 (a) 持有者 release（校验 pid+rand 归属）、(b) 持有者清理"自己换出的隔离文件"（名字含唯一 myRand，他人不可能触及）**。锁路径上无任何无条件 unlink。
