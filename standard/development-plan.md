### 阶段 B（后续节点·C1 工具落地）：申报绑定自动核验

- **内容：** ST-01 绑定申报核验脚本化，落 `toolkit/` 公共工具层（依赖方向：Basic/Standard=调用方不持有实现；toolkit=公共实现与测试；**不 import Standard 运行时模块**；Python 标准库；只读 Git 仓库，不修改工作区/分支/提交；输入不完整/对象不存在/无法确定时 fail-closed）。
- **测试矩阵（R1 补强版）：**

| 场景 | 预期 |
|---|---|
| 单 commit，parent=基线 | PASS |
| 多 commit，完整线性链 | PASS |
| 多 commit，parent 断链 | FAIL |
| 含 merge commit | FAIL＋提示改报 diff 基线 |
| 区间数量与申报数量不一致 | FAIL |
| 申报 SHA 不是最终待验收 commit | FAIL |
| 回填声明符合规则 | PASS，识别并排除指定范围 |
| 回填声明缺失或格式不完整 | FAIL |
| 基线或目标 commit 不存在 | FAIL |
| 空区间或对象范围无法确定 | 明确拒绝或提示不适用 |

- **工程要求：** ①逐条 parent 核验（不得仅凭 git show 首末 parent 判链）；②核验结果三态 PASS/FAIL/BLOCKED（无法核验≠PASS）；③断言具体拦截原因（命中规则/指向 commit/错误原因/处置建议，不只查 exit code）；④工具自身安全（错误输入/非法路径/异常 Git 输出→不修改仓库、不误判通过）。
- **验收标准：**
  - B1 上述矩阵全场景覆盖；
  - B2 负例逐项断言指名命中（L-017 正反例矩阵纪律）；
  - B3 实战：真实 Git 仓库＋真实任务包申报数据实跑，留存完整命令/输入/输出，绑定工具版本与测试 commit，对照人工核验结果，记录工具不能判定的边界；**实战结果不自动改 BC-06 状态**（按 Basic DoD 原有签核机制处理）；
  - B4 可复现性：同一输入＋同一 Git 对象＋同一工具版本→确定性判定；
  - B5 异常与安全边界：缺对象/权限异常/非法输入/Git 命令异常 fail-closed 验证（防矩阵全绿但真实环境误判 PASS）。
- **启动依据：** 设计输入 C1（强信号/优先级高/部分具备）——ST-01 绑定类跨 S1/S2/S3 复发 3 次含 P0。
- **范围红线：** C1 工具仅实现绑定核验，不顺带建设通用调度系统（H12）。
- **状态：** 待 R2 核对后按序实施。
