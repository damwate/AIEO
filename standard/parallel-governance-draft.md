## 1. M2 核心规则（一任务四件套）

**一任务、一执行会话、一独立 worktree、一任务分支。**

| 要素 | 规则 |
|---|---|
| 工作区 | 每任务独立 git worktree（共享对象库，独立目录与 index）；**禁止两个会话共用同一工作区或分支**；多 clone 为备用方案 |
| 分支 | task/<任务ID> 分支；登记基线完整 SHA/分支/worktree 路径于任务书 |
| 会话 | 开发会话与验收会话分离且不跨任务复用；开发会话不得跨任务 |
| 集成 | 禁止自动合并/自动 cherry-pick/无人确认 push；**main 合并仍须用户拍板（DEC-010）** |

## 2. 派单与采集（串行，不并行）

- session_lock 全局互斥**保留**；派单/采集人工 FIFO 队列；高优先级插队须记录原因。
- 每次派单核对 task ID/dispatch ID/conversation UUID；每次回复核对原始字节+SHA256。
- **禁止并发启动多个派单绕过锁**。
- 关键区分：**派单串行≠开发串行**——派单等待期间各 worktree 可同时开发。

## 3. 冲突与依赖管理

- 任务书登记：并行模式（M1/M2）/依赖任务/基线 SHA/worktree 路径/分支/文件所有权/开发会话/验收会话/冲突情况。
- **同文件同一时段只允许一个任务写入**；公共资源（WORKFLOW/decision-log/templates/全局配置/公共工具）默认独占。
- 依赖任务验收 PASS 前置，依赖任务才能进入相应开发步骤。
- 冲突处置：相关任务停止写入→登记 BLOCKED+原因→指定整合责任人→重新协商范围→重新独立验收。**禁止覆盖文件或盲目 rebase 消除冲突**。
- 优先级沿用任务书高/普通两级，不加复杂算法。

## 4. 试运行与复盘（五阶段）

1. **M1 继续**（现状，不变更流程）；
2. **M2 规则生效**（本文件经用户批准）；
3. **小规模实战**：最多 2 个并行任务，选低冲突/互不依赖/文件所有权清晰者；
4. **复盘统计**：工作区污染次数/文件与分支冲突次数/派单归属错误次数/验收会话串用次数/并行节省时间 vs 额外管理成本；
5. **决定扩大**：据实战证据决定扩大并行数与固化任务书字段；M3 另行讨论。
