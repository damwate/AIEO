# Standard 多任务模式实施方案 v0.1（设计稿——未生效，待复审+用户批准）

> **文档身份：** DEC-106④ 裁定产物（GO 顺序2："先完成架构、接口、任务隔离和风险评估，形成实施方案；暂不启用 M1 之外的能力"）。依据链：DEC-052（多任务移交中级版，Basic 维持 M1 交替）→ DEC-106④ → 本方案。**本方案是设计稿，不构成实施授权；实施分级放量每级另获批准。**

## 一、目标与范围

- **目标：** 将 M2 治理能力（多任务/多会话/多 worktree 安全并行，DEC-063 生效的 M2 规范候选）实施化——多任务**在 M1 平台与既有派单工具链内**安全并行。
- **范围边界（硬）：**
  - 暂不启用 M1 之外的能力（DEC-106④）；写操作链路 M4 仍封闭（DEC-106②暂不开放）；
  - ChatGPT 网页通道**保持全局互斥**（单 Chrome profile + 会话锁，既有实践零串位的基础不动摇）；
  - 验证门与 906 项⑥（M1 平台级并发）合并，不重复造场景。

## 二、架构设计

**现状：** M1 交替模式（一次一任务）；scheduler.py S0-S9 单任务编排；派单通道全局互斥（session_lock）+ reviewer 指针治理派单独占写。

**目标形态：任务级并行 + 通道级串行（资源互斥点收敛）。**

| 环节 | 并行性 | 依据（既有已验证实践） |
|---|---|---|
| 任务包准备/证据采集/文档 | **可并行**（纯本地） | b-20261117 多任务包并行编写 |
| git worktree | **可并行**（每任务独立） | 907/908 三 worktree 并存实测；runtime/t-p1-908 惯例 |
| M1 REST/登记/状态推进 | 可并发（幂等保障既有） | message dedup / ack idempotent / outbox 幂等重放全测 |
| 测试执行 Worker | 可并行（多 worktree） | test_worker.py 按传入 worktree 执行，无全局态 |
| **ChatGPT 派单通道** | **全局串行（互斥不动）** | session_lock v6（DEC-001"互斥交给内核"）；--no-update-pointer 保护 reviewer 指针 |
| ChatGPT 会话 | 任务-会话绑定（隔离） | 归属校验 sessionIdIsAttributable + extractBriefMarker 实战（L-018） |

**核心架构原则：** 并行度提升只发生在**非通道环节**；一切触碰浏览器/会话/指针的资源保持互斥——这是等级B试运行"零角色串位"的根基，不因多任务引入风险。

## 三、接口设计（scheduler 扩展面，最小增量）

1. **任务队列：** scheduler 入口从单任务改为队列输入（task-id 列表），逐任务独立 S0-S9 状态机实例；
2. **并发度参数：** `max_parallel`（默认 1=现状 M1 交替，语义不变）；并行仅作用于本地环节，派单环节排队；
3. **任务-会话绑定表：** `runtime/task-session-bindings.json`——task_id ↔ ChatGPT 会话 UUID ↔ 会话 user 消息计数（DEC-084 阈值按会话独立计数）；
4. **per-task artifact 命名空间：** 监控目录/证据目录按 task_id 分区（既有 dispatch-<ts>/ 天然按时间分区，增加任务字段）；
5. **互斥点显式化：** 派单锁（session_lock）与指针写锁合并为单一"通道闸"，接口文档登记唯一持有路径。

## 四、任务隔离设计

- **代码隔离：** 每任务独立 worktree（禁止共享工作树写）；
- **证据隔离：** dispatch 现场/五件套/recoll 按 task_id 分目录；C1 绑定按任务独立基线 commit；
- **会话隔离：** 一任务一（或一阶段一）ChatGPT 会话；跨任务禁止复用审查会话承载无关任务（远桥实例教训：同会话混项目靠标记文本区分，多任务下改为强隔离）；
- **失败隔离：** 单任务 fail-closed/即停不阻断队列其他任务；五类即停升级为全局版（任一任务触发权限越界/数据污染→全队列暂停）。

## 五、风险评估与缓解

| 风险 | 级别 | 缓解 | 残余 |
|---|---|---|---|
| 浏览器通道竞态 | 高 | 通道全局互斥不放松；排队+超时让路 | 低 |
| reviewer 指针漂移/串位 | 高 | --no-update-pointer 固化沿用；指针写仅治理派单 | 低 |
| M1 并发写冲突 | 中 | 幂等/去重/事务既有；先受控并发用例（906⑥）后启用 | 中（待验证门） |
| 会话阈值跨任务混计 | 中 | 绑定表 per 会话计数；迁移纪律照 DEC-084 | 低 |
| 证据串扰 | 中 | 目录隔离+C1 SHA 绑定+标记文本唯一 | 低 |
| 失败扩散 | 中 | 任务级 fail-closed；全局五类即停 | 低 |

## 六、实施序（分级放量，每级另批）

- **P0 设计评审：** 本文档 ChatGPT 复审 + 用户批准后冻结 v1.0；
- **P1 最小并行=2 任务（只读复审并行）：** 等级B模式的并行版——零写入零 M1 推进，五件套+复盘；
- **P2 平台级并发受控用例：** 解除 906⑥ 的验证门（REST+DB+ACK 真实并发最小场景）；
- **P3 并行度放开（≤3）：** 任务类型不限（仍零写入红线直至另行授权）；
- 每阶段完成复盘，不自动滚动；DEC-010 红线全程有效。
